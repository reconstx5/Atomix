# Win switchers with trust, reach, and skip features

The best additions for Atomix fall into three groups. First, make it **safe to live with**: built-in backup and restore with an automatic backup before every upgrade, a storage and health view, and `*arr` webhook receivers. Second, **extend skipping** past intros to credits and recaps, reusing the fingerprinting Atomix already has. Third, **reach more screens without writing native apps**, mainly through an opt-in subset of the Jellyfin-compatible API plus thin LG and Samsung TV wrappers around the existing web app. The timing is good. Plex put remote streaming behind a paid pass in April 2025 and then had a run of TV-app redesign backlash. Jellyfin's October 2025 database migration cost some users their watch history. Both events sent people looking for a free, stable, TV-first alternative, which describes Atomix. Atomix already covers most of the long-standing top requests on Plex's vote-sorted board (comics and books, audiobooks, Watch Together, smart playlists). The remaining gaps are mostly not new media types. They are operations, interoperability, household sharing and music polish. The large category bets, a photo library and virtual channels built from your own library, have real demand, but they belong after the cheaper trust and reach work. The ranked shortlist at the end turns this into a build order.

## Plex's paywall and Jellyfin's migration left a stability-shaped opening

Plex's 2025–2026 changes pushed away the kind of user Atomix serves. From April 29, 2025, streaming from a server outside the home needs **a Plex Pass or a new Remote Watch Pass**, and the Plex Pass price went up at the same time ([9to5Mac](https://9to5mac.com/2025/03/19/plex-price-increase-remote-streaming-changes/); [Plex blog](https://plex.tv/blog/important-2025-plex-updates/)). Sources quote the Remote Watch Pass at different prices: $1.99/month in early coverage ([iClarified](https://www.iclarified.com/96773/plex-announces-price-hikes-remote-watch-pass-subscription-more)) and $2.99/month in later reporting ([Android Authority](https://www.androidauthority.com/plex-price-hikes-get-jellyfin-3663600/)). The lifetime pass then went **from $249.99 to $749.99 in July 2026**, announced alongside new social features (Discussions, shareable Lists, a "Match Score" and Alerts) ([TechCrunch](https://techcrunch.com/2026/06/03/plex-launches-new-social-features-amid-a-major-price-hike/)). People who switched say they object to paying to reach their own files, name Tailscale as the free alternative, and say they miss Plex's polish and the watch history that doesn't come with them ([Android Authority](https://www.androidauthority.com/plex-price-hikes-get-jellyfin-3663600/)). Atomix's free Tailscale HTTPS and its support for connected Plex servers already answer the money complaint. A **one-click import of watched state and ratings from Plex or Jellyfin** would answer the history complaint. Community tools such as JellyPlex-Watched exist only because the servers don't offer this themselves.

The TV-app backlash works as a spec for what not to do. In Plex's 2026 Fire TV redesign, a pinned library sidebar became a top menu that users called "designed for mouse and keyboard, not for TV". Users reported that an action went from about two clicks to about six, that menus were hard to leave, that posters lagged while scrolling, that local playback took more than 30 seconds to start, and that there was no way to opt out ([PiunikaWeb](https://piunikaweb.com/2026/05/04/plex-fire-tv-redesign-unusable-users-slam-navigation/)). A Roku update in September 2025 caused similar complaints ([PiunikaWeb](https://piunikaweb.com/2025/09/17/plex-roku-update-backlash)). Atomix's D-pad-first Preact app is its best defence here. The lesson is to measure clicks-to-play and time-to-first-frame as regression metrics, not to add new chrome.

Jellyfin had the opposite problem: an infrastructure release that hurt users. Version 10.11 (October 2025) moved to a single EF Core database. Users then reported **multi-hour startup migrations, corruption, and lost watch history for anyone without a backup**, and the standard advice became "back up /config first and wait for a point release" ([JellyWatch summary of forum and GitHub reports](https://jellywatch.app/blog/jellyfin-10-11-ef-core-migration-chaos-lessons-learned-2026)). The same release also brought the features that now count as the operations baseline: built-in scheduled backup and restore, a startup log viewer, a refusal to start with **less than 2 GB free**, a storage dashboard, and the deprecation of built-in TLS in favour of reverse proxies ([Jellyfin 10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0); [GitHub release](https://github.com/jellyfin/jellyfin/releases/tag/v10.11.0)). Jellyfin's restore works only on the same machine. If Atomix stored relative paths and added a path-remap step on restore, its backups would also work as **migration across hosts**, for example from a home PC to a VPS. That matches Atomix's "run locally or as its own server" pitch, and Jellyfin doesn't offer it.

Plex shows that admins want to see their server's state, not just configure it. Its July 2026 **Server Dashboards** in the mobile and TV apps show live sessions, bandwidth, CPU and memory, top users and per-user history ([Plex forum](https://forums.plex.tv/t/server-dashboard-release/941143)). Atomix already has activity logs and stats. Adding live resource charts, per-library free space (Node's `fs.statfs`), a scheduled-tasks page with "Run now", and a `/health` endpoint for Docker would cost little and needs no new dependencies.

## Skipping, sharing and `*arr` plumbing are cheap wins on existing code

**Credits and recap skip** is the highest-value playback addition. Infuse 8.4 (March 2026) skips **intros, credits and recaps** using community timestamp databases (IntroDB.app, TheIntroDB.org), and users can submit their own timestamps ([Firecore blog](https://firecore.com/blog/infuse-84-extras-intros-and-favorites)). Channels 7.0 added intro detection in October 2025 ([Channels blog](https://getchannels.com/blog)). Jellyfin's Intro Skipper plugin, the reference open implementation, combines **Chromaprint fingerprinting with silence and black-frame detection** ([Intro Skipper README](https://cdn.jsdelivr.net/gh/intro-skipper/intro-skipper@10.11/README.md)). Atomix already fingerprints intros and reads credits from chapter names. Running ffmpeg's `blackdetect` and `silencedetect` over the last minutes of each file, and fingerprinting across episodes, would produce credits markers that drive a "Next episode" prompt. Matching an episode's opening against the previous episode would catch recaps. Reading from IntroDB-style databases fills in what local detection misses. Effort is low to medium, and none of it needs a new dependency.

**Friend and remote sharing** turns several user complaints into one feature. "Default All Clients to Max Internet Streaming" has **1,727 replies**, the most of any thread on the first page of Plex's vote-sorted suggestion board. "Send server messages" has 634 ([Plex forum votes](https://forums.plex.tv/c/feature-suggestions/8/l/votes)). Emby 4.9.3 (January 2026) added a **per-user automatic remote-quality setting** ([Emby forum](https://emby.media/community/topic/145657-emby-server-493-released)). Wizarr shows the invite pattern people expect: a link that creates an account, a guided app-setup wizard, time-limited membership and library-scoped access ([ElfHosted: Wizarr](https://docs.elfhosted.com/app/wizarr/)). Atomix has Quick Connect and the transcoder. It lacks invite links, a per-user remote bitrate cap and a concurrent-stream limit, and these three together are what a VPS deployment shared with friends needs. Atomix's notifications plugin only sends outbound webhooks to admins. Pointing it at users as well, with a "new on the server" digest, would cover the 2025 request to tell shared users about new content ([Plex Pro Week '25 thread](https://forums.plex.tv/t/pro-week-25-fireside-in-the-forum-question-submissions/930736/154)).

**`*arr` integration** is mostly receiving events, not building a request system. Overseerr and Jellyseerr merged into **Seerr v3.0.0 on 2026-02-14**, which supports Plex, Jellyfin and Emby only ([newreleases: Seerr v3.0.0](https://newreleases.io/project/github/seerr-team/seerr/release/v3.0.0)). Media servers fit into this ecosystem through refresh hooks. Autopulse, for example, receives Sonarr/Radarr/Lidarr "Connect → Webhook" posts on import, upgrade, rename and delete, then **rescans only the affected path** instead of the whole library ([Ultra.cc: Autopulse](https://docs.ultra.cc/unofficial-application-installers/autopulse)). Atomix can do the same natively with a `POST /api/library/scan {path}` endpoint and parsers for the `*arr` webhook JSON. That is a few days of work for a server that already scans. A "Request this" button on titles that appear in TMDB search but not in the library can link to the user's Seerr instance rather than rebuild Seerr's quotas and approval flow. For Seerr to list Atomix as a server, though, Atomix has to speak Seerr's Jellyfin scanner protocol. That ties this item to the interoperability work in the next section.

## A Jellyfin-compatible API is the biggest reach lever

Atomix's client reach is its weakest point structurally. iOS PWAs need iOS 16.4+ and a home-screen install before Web Push works. Their script-writable storage can be evicted. **In the EU since iOS 17.4, standalone PWAs, push and badges have been removed**, and no reversal had been reported as of March 2026 ([MagicBell](https://www.magicbell.com/blog/pwa-ios-limitations-safari-support-complete-guide)). That makes "new episode" pushes and offline downloads on iPhones unreliable. A PWA can't run on CarPlay, Android Auto, Apple TV or Roku at all.

The fix that has worked elsewhere is to imitate the Jellyfin API rather than write native apps. **Navidrome 0.64.0 ships an opt-in Jellyfin API at `/jellyfin`**. It covers browse, search, favourites, playlists, streaming with transcoding and ReplayGain, lyrics, scrobbling, Instant Mix, Quick Connect and UDP 7359 discovery, and it is tested with Finamp, Jellify and Feishin. Video and Live TV are left out ([Navidrome docs](https://www.navidrome.org/docs/usage/features/jellyfin/)). **Prismedia's compatibility layer goes further and works with Infuse for video**, as well as Manet, Finamp and Symfonium for audio. It supports series, Next Up, direct play or HLS fallback, and two-way progress sync ([Prismedia docs](https://pauljoda.github.io/Prismedia/docs/jellyfin/overview)). One 2026 guide counts **70+ Jellyfin client apps** ([JellyWatch](https://jellywatch.app/blog/awesome-jellyfin-clients-complete-ecosystem-guide-2026)). Home Assistant's built-in Jellyfin integration creates a media_player entity for each session ([Home Assistant](https://home-assistant.io/integrations/jellyfin)). So one API layer could bring Atomix to Apple TV through Infuse, to CarPlay through Finamp, and into Home Assistant automations, and make it visible to Seerr.

This is the most expensive item on the shortlist and has the most risk, so it should be phased. Phase one would cover public system info, authenticate-by-name, user views, `/Items` with paging and filters, images, seasons and episodes, stream endpoints, and progress reporting. It should target only Infuse and Finamp, the two clients where third-party servers have already succeeded. That is roughly two to four weeks of work, mostly matching JSON shapes and ID formats. Clients that depend on `PlaybackInfo` device-profile negotiation, such as Swiftfin, Findroid and Streamyfin, come later. No source confirms that they tolerate a partial server. Infuse compatibility has so far been worked out by trial and error, and Firecore publishes no endpoint list ([Firecore community](https://community.firecore.com/t/developing-my-own-jellyfin-compatible-server-api-question/53657.md)). The API also moves: 10.11 deprecated the old playback-report calls, and deprecated auth methods are due to be removed in 10.12 ([Jellyfin 10.11.0 release post](https://jellyfin.org/posts/jellyfin-release-10.11.0)). Atomix should write the wire format from scratch, keep Jellyfin's name and logos out of the product, and log unhandled routes the way Navidrome does. Imitating the Plex API is not worth attempting, because Plex clients depend on plex.tv's account system.

For TVs that have a browser engine, the cheaper route is a wrapper. **jellyfin-webos is "a small wrapper around the web interface provided by the server"**, packaged with LG's `ares` CLI and listed in the LG Content Store ([GitHub: jellyfin-webos](https://github.com/jellyfin/jellyfin-webos)). Atomix's no-build Preact app with remote navigation fits this pattern closely: a server-URL screen, a redirect, and a Back/colour-key mapping, which can be sideloaded immediately. Samsung is harder. Jellyfin reached the Tizen store only in **early 2026, after about three years of work and a failed first review**, and only for 2021+ models ([SamMobile](https://www.sammobile.com/news/jellyfin-app-samsung-tv-launched-plex-alternative/)). Atomix can ship a sideloadable `.wgt` package and treat a store listing as a long-term goal.

On the web side, Atomix's player can do more with what browsers already support. HEVC now plays in Chrome/Edge and in Firefox on Windows (134+), macOS (136+) and Linux (137+, MP4 only), but only where hardware decoding is available. Some Firefox Windows 10 cases are still broken ([Neowin](https://www.neowin.net/news/firefox-134-finally-gets-windows-hardware-h265-support-improves-popup-blocking-and-more/); [Jellyfin forum](https://forum.jellyfin.org/t-firefox-137-0-now-supports-hevc-playback-on-linux?pid=56890); [Bugzilla 1956489](https://bugzilla.mozilla.org/show_bug.cgi?id=1956489)). Apple supports AV1 hardware decode from A17 Pro and M3 ([Bitmovin](https://bitmovin.com/blog/apple-av1-support/)). Managed Media Source brings MSE-style adaptive streaming to iPhone Safari 17.1+ ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/managed-media-source)). Atomix could probe each client's codec support and direct-play HEVC or AV1 where the client can decode it, and remux MKV to fMP4 for Firefox instead of re-encoding. That would reduce transcoding on small VPSes. The coordinator did not check how Atomix currently negotiates codecs, so this item should be audited before it is built. Screen Wake Lock has been Baseline since March 2025 ([web-features](https://web-platform-dx.github.io/web-features-explorer/features/screen-wake-lock)). Document Picture-in-Picture now works in Chromium and in Firefox 151, though not in Safari ([web.dev](https://web.dev/blog/web-platform-05-2026)). Both are small progressive enhancements: a mini-player that can show the EPG or subtitles, and phones that stay awake while used as a remote.

## Local AI and music depth are now practical without new npm packages

The stack Atomix is built on, Node plus ffmpeg, now covers more ground. **FFmpeg 8.0 (August 22, 2025) added a `whisper` audio filter** built on whisper.cpp ([Linuxiac](https://linuxiac.com/ffmpeg-8-0-arrives-with-whisper-filter-vulkan-encoders); [The Register](https://www.theregister.com/2025/08/28/ffmpeg_8_huffman/)). On an ffmpeg build that includes it, Atomix could generate subtitles for files that have none, and transcripts for DVR recordings, with a single job-queue command and no new dependency. The speeds are workable at home scale. One benchmark transcribed a 13-minute clip with the small model on CPU in **2m37s, about 5x realtime**. On GPU, large-v2 took about a minute ([Codersera](https://codersera.com/blog/faster-whisper-vs-whisper-cpp-speech-to-text-2026/)). Extrapolating, a feature film on a modest CPU would take something like 25 minutes, run overnight. The main risk is packaging: many distro builds of ffmpeg will lack the filter, so Atomix needs to detect it and fall back to a `whisper-cli` binary. Translation should call a user-configured endpoint such as LibreTranslate or a local LLM rather than bundle models. Lingarr shows that pattern working ([SelfHostYourself: Lingarr](https://selfhostyourself.com/services/lingarr)).

Music is where Atomix most clearly trails, and the gaps are well defined. Users comparing self-hosted music servers single out **gapless playback, ReplayGain, queue management, artist radio, smart playlists and M3U import**. They call Plexamp the best app, and it requires Plex Pass ([dev.to selfhosting.sh](https://dev.to/selfhostingsh/navidrome-vs-jellyfin-for-music-which-should-you-self-host-23f0)). On Plex's board, requests for multi-artist albums (314 replies), robust tagging (254) and CUE for FLAC (209) remain open ([Plex forum votes](https://forums.plex.tv/c/feature-suggestions/8/l/votes)). Atomix has none of gapless, ReplayGain or crossfade. Loudness is the easiest to add. Running an `ebur128`/`loudnorm` analysis pass at scan time, storing LUFS and true peak in SQLite, and applying gain through a Web Audio GainNode or during transcode would also feed the existing Subsonic API, where ReplayGain fields are expected. Gapless and crossfade need Web Audio scheduling or two decoders in the browser, which is harder. Navidrome 0.59 added recorded listen history as groundwork for "wrapped"-style summaries ([Linuxiac](https://linuxiac.com/navidrome-0-59-music-server-streamer-introduces-scrobble-history/)). Through AudioMuse-AI, Navidrome now serves the **OpenSubsonic `sonicSimilarity` extension** (instant mix, similar tracks, "sonic path" transitions) ([Navidrome docs: AudioMuse](https://navidrome.org/docs/usage/integration/audiomuse/)). Adding OpenSubsonic extensions to Atomix's existing Subsonic API, and connecting to AudioMuse-AI as an external service, would bring these features to Symfonium and similar clients without Atomix building its own analysis engine.

Photo libraries are the largest category gap, and demand for them is consistent. Users asked for HEIC/HEIF support (230 replies on the Plex board) ([Plex forum votes](https://forums.plex.tv/c/feature-suggestions/8/l/votes)), an image gallery and 360° content ([Jellyfin forum](https://forum.jellyfin.org/f-feature-requests)), and "Immich parity without Docker" ([Plex Pro Week '25](https://forums.plex.tv/t/pro-week-25-fireside-in-the-forum-question-submissions/930736/154)). The AI part is not the hard part. **On a 2018 four-core NUC with no GPU, Immich embedded 51,126 images for CLIP search in under an hour, and answered a text query in 0.038 s** ([mustafa.net](https://mustafa.net/2026/10/10/immich-without-gpu-intel-nuc/)). The hard part is everything that surrounds a good photo app: automatic mobile backup, faces, maps, memories, and duplicate review like Immich 2.2's ([Immich blog](https://immich.app/blog/v2.2.0-release)). These take months to build and need ONNX runtimes that conflict with Atomix's no-npm rule. An **Immich connector**, built the same way Atomix already connects to Jellyfin, Emby and Plex, plus a basic photo and home-video library type with HEIC thumbnails through ffmpeg, would meet most of the demand at a fraction of the cost.

Virtual channels built from your own library are the most distinctive feature for Atomix specifically. "PseudoTV" has 237 replies and multiple EPG sources has 278 on Plex's board ([Plex forum votes](https://forums.plex.tv/c/feature-suggestions/8/l/votes)). Today the feature exists only in separate tools. **ErsatzTV, Tunarr and dizqueTV** build scheduled channels with filler and bumpers and export M3U plus XMLTV ([PiStack](https://www.pistack.xyz/posts/2026-06-12-self-hosted-virtual-tv-channels-ersatztv-tunarr-dizquetv/)). Atomix already has a Live TV guide, an M3U/XMLTV pipeline and DVR, so "channels from my library" could reuse almost all of that interface. The remaining work is a scheduler and an always-on or on-demand transcoder for each channel, which is medium effort. Multiview, which Channels shipped in 7.0 ([Channels blog](https://getchannels.com/blog)), and commercial detection for recordings are worth considering too. But multiview is expensive to decode in a browser, and no 2025–26 source was gathered on how much demand there is for commercial detection, so both rank lower.

## Ranked shortlist for Atomix

Items are ordered by how well they fit, considering value to Atomix's likely users, reuse of existing code, effort, and how well they respect the no-npm-dependency rule. Effort assumes one experienced developer: Low is under a week, Medium is one to three weeks, and High is a month or more.

| # | Feature | Why it fits Atomix | Rough effort | Dependencies and risks |
|---|---|---|---|---|
| 1 | **Backup and restore, with automatic pre-upgrade backup and a cross-host path remap** | It answers the most-reported maintenance pain (Jellyfin 10.11 data loss). Portable restore also supports the "move from home to VPS" story, which Jellyfin doesn't offer. | Low–Medium | Tar/zip using Node core. Restore has to handle schema versions. The path remap needs careful testing on Windows and Linux. |
| 2 | **Credits and recap detection, plus a community timestamp source** | It extends the existing fingerprinting and chapter markers. It matches Infuse 8.4 and drives a "Next episode" prompt. | Low–Medium | ffmpeg `blackdetect`/`silencedetect`. IntroDB-style APIs are third-party and may change or rate-limit. False positives on cold opens. |
| 3 | **`*arr` webhook receivers, scan-by-path, and a "Request this" link to Seerr/Radarr/Sonarr** | Low-cost plumbing that power users expect. Partial rescans keep large libraries fast. | Low | Payload formats are unversioned. Atomix won't appear inside Seerr as a server without #6. |
| 4 | **Friend sharing: invite links with expiry and library scope, per-user remote bitrate cap, stream limit, and user-facing "new on server" notifications** | It turns the top Plex grievance (1,727 replies) and Emby 4.9.3's feature into one VPS-ready workflow built on Quick Connect and the transcoder. | Medium | Abuse and security surface on public servers. Needs rate limiting and invite revocation. |
| 5 | **Server health dashboard and scheduled-tasks page** (live CPU, RAM and bandwidth, free space per library, refuse risky tasks when low on space, `/health` endpoint) | Plex and Jellyfin both shipped this in 2025–26. It builds on Atomix's existing activity log and stats. | Low | `fs.statfs` needs Node 18.15+. CPU metrics differ across platforms. |
| 6 | **Opt-in Jellyfin-compatible API, phase one targeting Infuse and Finamp** | It is the only realistic route to Apple TV, CarPlay/Android Auto, Home Assistant and Seerr without native apps. Navidrome and Prismedia show it works. | High | Clients are reverse-engineered and drift between Jellyfin versions. Video clients that use `PlaybackInfo` may not work. Avoid Jellyfin branding. Ongoing maintenance cost. |
| 7 | **Loudness normalisation and gapless playback for music, and OpenSubsonic extensions including sonic similarity via AudioMuse-AI** | It closes the clearest music gap and improves both the web player and third-party Subsonic clients. | Medium (loudness Low; gapless Medium) | ffmpeg `ebur128` scan time on large libraries. Gapless needs Web Audio scheduling. AudioMuse-AI is a heavy external Docker stack. |
| 8 | **Whisper subtitles (and optional translation) as a background job** | Uses the ffmpeg 8 built-in filter with no npm dependency. Fills subtitle gaps and adds DVR transcripts. | Low–Medium | Many ffmpeg builds lack `--enable-whisper`, so a binary fallback is needed. CPU time (about 5x realtime with small). Model downloads of 1–3 GB. |
| 9 | **LG webOS and Samsung Tizen wrapper apps** | The Preact app with remote navigation already does the hard part. This copies Jellyfin's working approach. | Low (sideload) / High (store listing) | Store review took Jellyfin about three years on Tizen. Only 2021+ Samsung models can be published. Key-code quirks. |
| 10 | **Virtual channels from your own library** | Reuses Live TV, the EPG, M3U/XMLTV and the DVR. Steady demand ("PseudoTV"), and nothing comparable is built into a hub today. | Medium | Each live channel needs an ongoing transcode. Scheduling rules can grow complex, so start with shuffle and time-block channels. |
| 11 | **Codec-capability probing for direct play of HEVC/AV1, MKV-to-fMP4 remux, and Managed Media Source on iPhone** | Less transcoding on a small VPS. Uses browser support that improved in 2025–26. | Medium | Browser support depends on hardware and has known Firefox bugs. Verify what Atomix already negotiates before scoping. |
| 12 | **OIDC sign-in and TOTP in core** | SSO is plugin-only in Jellyfin, so shipping it in core would set Atomix apart. Both can be hand-rolled with `crypto` and `fetch`. | Medium | Security-critical code written without a library. Native and compatibility clients still need local passwords or API keys. |
| 13 | **Watch-history import (Plex/Jellyfin), Letterboxd CSV export, then Trakt sync** | Removes the main reason switchers hesitate to leave. CSV avoids storing Letterboxd passwords. | Low–Medium | Matching by TMDB/IMDb IDs. Trakt API terms and rate limits were not checked. |
| 14 | **Movie editions and multiple versions** | 806 replies on Plex's board. Kodi 22 improved importing multiple versions. Fits remote-vs-local quality choice. | Medium | Changes the library schema and the scanner's naming rules. |
| 15 | **Photo and home-video library (HEIC via ffmpeg), with an Immich connector before native AI** | The largest category gap, with consistent demand. A connector matches Atomix's existing connected-servers design. | Medium (connector) / High (native AI) | Native CLIP and face recognition need ONNX runtimes, which conflict with the no-npm rule. Immich's API changes between versions. |

Household polish should go alongside #4 rather than as separate items: a guest profile, hiding the admin account from "Who's watching?", and per-device lists of allowed profiles. Jellyfin users asked for exactly these in May 2026 ([Jellyfin forum](https://forum.jellyfin.org/t-first-class-household-profiles-for-shared-devices)). Multiview, commercial detection, a screensaver or ambient mode, and voice assistants are left off the shortlist. Google Home control is the #3 request on Plex's board ([Plex forum votes](https://forums.plex.tv/c/feature-suggestions/8/l/votes)), but for Atomix it is best reached through Home Assistant once #6 exists, or through play/pause events sent via the existing webhook plugin.

## Conclusion

The research contradicts the obvious instinct that Atomix should add more media types. Atomix already has the breadth that Plex users spent years voting for. The features that would bring switchers over and keep them are mostly unglamorous: never losing someone's history, never needing a full rescan, letting a friend in with a link, and playing well with the tools people already run (Sonarr, Seerr, Infuse, Home Assistant). Plex is moving its effort toward social features and paywalls, and Jellyfin is still recovering from its migration, so being dependable is itself the differentiator.

The one strategic bet worth making is the Jellyfin-compatible API, because it changes Atomix's position from "another server that needs its own apps" to "a server that existing apps can already use". It is also the riskiest item, since Atomix would be tracking an API it doesn't control. The sensible order is to ship items 1–5 first, which are low-risk and make Atomix trustworthy. Then build a narrow Infuse-and-Finamp version of the compatibility layer and judge from real client behaviour whether to extend it to video-first clients like Swiftfin.
