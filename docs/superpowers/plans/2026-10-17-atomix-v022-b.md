# Atomix Round 24 — Plan B (Podcasts and audiobooks on the server; v0.22.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two new library types — Podcasts (feeds the server checks, episodes it keeps) and Audiobooks (folders and .m4b files with chapters, one timeline per book) — that work with Kids rules, progress, search, playlists, Downloads, stats and music apps; plus Plan B's v0.21 download leftovers.

**Architecture:** New `libraries.type` values `podcasts` and `audiobooks`; new `items.kind` values `podcast`, `podcast_episode`, `audiobook`, `chapter` (one file of a multi-file book). Feed and episode bookkeeping lives in two new tables (migration 25); everything a title needs (title, overview, poster, `min_age`, duration, path) stays on `items`, so the existing viewer rules, progress and serializers apply. A `Podcasts` service owns subscribe/check/download/keep; the scanner gains an audiobooks pass.

**Tech Stack:** Node ≥ 22.13 (`node:test`, `node:sqlite`, `fetch`), ffmpeg/ffprobe, the existing DOM-free XML reader `public/js/dash/xml.js` (`parseXml`).

**Spec:** `docs/superpowers/specs/2026-10-17-atomix-v022-design.md` section 2 and section 5 (Plan B leftovers).

## Global Constraints

- No dependencies; no Kodi GPL code; no DRM circumvention.
- Feed, enclosure, directory and artwork addresses never reach the browser or the logs (`redactUrl` in logs); the browser only sees Atomix's own addresses.
- Kids never see admin data (feed status, feed errors, keep settings) and never a title outside their rules.
- Feed limits (exact): 5 MB of XML; 500 episodes read per check. Default check interval 6 h (setting `podcastCheckHours`, 0 = off). Default keep: newest 10; deleting played episodes outside the kept set on by default; unplayed ones never deleted.
- Every server-side fetch goes through `fetchFollowing(url, { check: (u) => checkResolved(u) })` — the same address rule as artwork and connected servers.
- Copy (exact): "Couldn't reach the feed (N tries since <weekday>)" (N ≥ 2; one failure: "Couldn't reach the feed"); "That isn't a podcast feed."; "That feed is too big (over 5 MB)."; "That address can't be used." (a refused address); "You already follow this podcast."
- Past 95% a podcast episode or an audiobook counts as played (films and episodes keep 90%).

## Decisions this plan makes (spec silent or loose)

- **Migration 25** (Plan A took 24).
- **XML:** the spec's "the XML reader the Live TV guide uses" becomes `public/js/dash/xml.js` `parseXml` (the server already imports it for DASH; the guide's reader is a streaming XMLTV-only parser), with limits `maxBytes: 5 MB`, `maxNodes: 200 000`.
- **Directory:** Apple's iTunes Search API (`/search?media=podcast&entity=podcast&term=`, `/lookup?id=`), base `ATOMIX_PODCAST_DIRECTORY` (default `https://itunes.apple.com`). The browser sends the directory's `collectionId`, never a feed address it was shown; result pictures are served through Atomix (`/api/podcasts/directory/:id/art`, from the last search's results, kept 10 minutes).
- **Which episodes are downloaded:** the newest N by publication date plus every kept (pinned) one. Older episodes are listed (title, date, length) but have no file until kept. Audio enclosures only (`audio/*` or an audio extension); a video enclosure is listed with `status: 'unsupported'` and not downloaded.
- **"Played" for deletion:** at least one profile has it played and no profile is part-way through it.
- **Unsubscribe** deletes the podcast's rows and its downloaded files (they are Atomix's copies, inside the podcasts folder only).
- **Multi-file audiobook:** an `audiobook` row with `path` NULL and `chapter` children (one per file, natural-sort order, `parent_id` and `show_id` = the book). A single-file book is an `audiobook` row with its own `path`. Progress is saved on the `audiobook` row, position = seconds into the whole book.
- **Playlists:** song playlists also take podcast episodes and audiobooks (the error becomes "A song playlist takes songs, podcast episodes and audiobooks.").

## Review Focus

1. **A feed whose episodes have no GUID, or the same GUID twice, or change their enclosure address** — episodes are matched by GUID, else by enclosure URL, else by title + date; a changed enclosure on a known episode doesn't download it twice (Task 2 / Task 3 tests).
2. **The server restarts mid-download** — the `.part` file resumes with a Range request; a server that ignores Range (200) starts over; a finished file is never left as `.part` (Task 3 test).
3. **An admin removes the podcasts folder's files by hand, or the disk is full** — a missing file makes the episode "Not downloaded" again (re-downloaded at the next check if it's in the kept set); a write error marks the episode failed with its sentence and the next check retries (Task 3 test).
4. **A Kids profile and an explicit feed later rated by an admin** — Edit details' age rating wins over the explicit flag and survives the next feed check (Task 3 test).
5. **An audiobook folder with mixed parts (cover image, .cue, a stray .txt, disc subfolders "CD1", "CD2")** — only audio files count; disc subfolders join their parent book in order; the cover image becomes the poster (Task 4 test).

### Task 3: The Podcasts service and its routes

**Files:**
- Create: `src/podcasts/index.js` (class `Podcasts`), `src/api/podcasts.js`
- Modify: `src/app.js` (construct and `start()`/`stop()` with the app; register routes), `src/api/library.js` (`GET /api/items/:id` for `podcast`: episodes; for admins `feed` status), `src/settings.js` (`podcastCheckHours` default 6)
- Test: `test/podcasts.test.js`

**Interfaces:**
- Consumes: `parseFeed`, `episodeKey`, `fetchFeed` (Task 2); migration 25 (Task 1); `images.download` for the show's and episodes' pictures.
- Produces:
  - `class Podcasts { constructor({ db, library, images, settings, config, log }); start(); stop(); subscribe({ feedUrl } | { directoryId }) -> podcastRow; check(podcastId) -> { found: number, queued: number, removed: number }; checkAll(); setKeep(podcastId, { keep: number|'all', deletePlayed: boolean }); keepEpisode(episodeId, kept: boolean); unsubscribe(podcastId); feedStatus(podcastId) -> { checkedAt, error, failures, errorSince, keep, deletePlayed }; directory(term) -> [{ id, name, author, artwork }] }`.
  - Downloads: one at a time per server (a queue in the service); written to `<folder>/<show>/<YYYY-MM-DD> <title>.<ext>` (names cleaned of `\ / : * ? " < > |` and control characters, ≤ 120 characters); `.part` while downloading, resumed with `Range: bytes=<size>-` (a 200 answer starts over); on success the episode's `items.path`, `size`, `duration` (ffprobe when the feed had none) are set and status `done`. Failure: status `failed`, `error` the sentence, retried at the next check.
  - Keep rule after each check: the kept set = newest `keep_count` (all when NULL) + `kept = 1`; episodes in it without a file are queued; with `delete_played`, files of played episodes outside it are deleted (see "Played" decision) and status back to `new`. Files are only ever deleted inside the library's folder.
  - Missing files: a check finds an episode whose file is gone → `path` NULL, status `new` (re-queued if in the kept set).
  - Explicit: a podcast's `min_age` is 18 when the feed says explicit, unless `min_age` is locked by Edit details (`locked_fields` contains `certification`).
  - Routes (admin unless noted): `GET /api/podcasts/directory?q=`; `GET /api/podcasts/directory/:id/art`; `POST /api/podcasts` `{ libraryId, feedUrl } | { libraryId, directoryId }` → 200 the podcast (409 "You already follow this podcast."); `POST /api/podcasts/:id/check`; `PATCH /api/podcasts/:id` `{ keep, deletePlayed }`; `DELETE /api/podcasts/:id`; `PUT /api/podcasts/episodes/:id/keep` `{ kept }`. `GET /api/items/:id` of a `podcast` (any viewer who may see it): `episodes` newest first, each with `status`, `publishedAt`, `duration`, `progress`, `kept`; `feed` (status) only for admins on a grown-up profile.
  - Scheduler: `checkAll()` every `podcastCheckHours` (0 = off), the first 2 minutes after start.

- [ ] **Step 1: Failing tests** (`test/podcasts.test.js`, a fake feed server serving RSS and MP3 enclosures made with `makeAudio`)

  - `a new episode is found and the oldest kept-set member moves out`: with `keep: 3`, a 13th episode → it downloads; a played episode outside the set has its file deleted; an unplayed one keeps its file.

  - `a missing file is downloaded again`: delete a kept episode's file → after a check it's `done` again.
  - `an episode whose enclosure address changes isn't downloaded twice`: the same GUID with a new enclosure URL → one episode, its file kept, no new download; two items with no GUID and different enclosures → two episodes.
