# Atomix v0.27.0 Plan C: Watch on TV (casting encrypted channels) and the release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An encrypted Widevine or ClearKey channel can be cast to a Chromecast or Google TV, which decrypts it with its own Widevine. Phones that can't play a channel offer **Watch on TV**. Then v0.27.0 ships.

**Architecture:**
- **The server:** the cast manager opens a `LiveDrm` session for the TV and keeps it alive itself. A cast link scoped to that one DRM session lets the TV fetch the manifest, segments, clock and licence without a sign-in.
- **The manifest for a TV:** the manifest the TV gets has absolute addresses carrying the link, plus a `dashif:Laurl` naming Atomix's licence route, so Google's standard receiver (Shaka) asks Atomix for the licence.
- **The browser:** Cast to… allows encrypted channels for Chromecasts only, and the player, the older themes' "…" menu and the Orbit spotlight offer Watch on TV on touch devices.

**Tech Stack:** Cast v2 (`src/cast/chromecast.js`), `src/live/drm.js`, the cast links (`src/cast/tokens.js`). Node's test runner with `test/helpers-cast.js` `fakeChromecast`/`fakeDlna`; Playwright with `/home/claude/devtools/mock-cast.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-22-atomix-v027-phone-live-tv-design.md` (§3, Verification, Plans). Plans A and B are done:
- `NO_WIDEVINE_IPHONE` and `NO_WIDEVINE` (`dash/eme.js`);
- `protectionOf` (`live.js`);
- the `refused(err)` path in `views/player.js`;
- v027-ui sections `https`, `secure`, `phone`, `nowv`.

## Global Constraints

- **No DRM circumvention.** The TV decrypts with its own Widevine, and Atomix only relays. Provider addresses, headers and tokens never reach the TV, a browser or a log. The cast link is never forwarded to the provider.
- **Nothing changes for other platforms:**
  - plain channel casts load exactly as in v0.26;
  - DLNA keeps refusing encrypted channels;
  - FairPlay can't be cast.
- **Kids rules, the provider's stream limit and the account's 4 streams** apply to the TV's DRM session. Encrypted channels stay live only.
- **No npm install, no build step, no new libraries.**
- **Older themes stay pixel-identical:** `oldthemes-compare.mjs compare` → "all pages match". The Watch on TV buttons appear on touch devices only (`matchMedia('(pointer: coarse)')`); compare runs on desktop.
- **Copy, verbatim:**
  - "This TV can't play encrypted channels; use a Chromecast or Google TV"
  - "Encrypted channels need a Chromecast or Google TV on your network. Plain channels still play here."
  - "Watch on TV"
  - FairPlay casts are refused with the existing "This channel is encrypted, so it can't be cast".
- **Values:**
  - the TV's LOAD is `contentType: 'application/dash+xml'`, `streamType: 'LIVE'`, with the channel's name and logo;
  - `<dashif:Laurl xmlns:dashif="https://dashif.org/CPS">` sits inside each kept `ContentProtection` (Widevine or ClearKey);
  - the link lives **12 h**, or until the cast ends.
- **Process:** never `pkill -f`; browser suites one after another; restart the dev server after server changes; no git in the cloud copy (the ledger records each task); hash PC files before overwriting.

## Review Focus

1. **Channel up/down on the TV between an encrypted and a plain channel, on a 1-stream provider.**
   - The next channel starts (replacing the old one's slot), then the old one stops.
   - No DRM session or playback session is left behind.
   - Test: Task 1, `zapping on the TV between an encrypted and a plain channel on a 1-stream provider leaves one stream`.
2. **The cast link used anywhere else**, whether another DRM session, a library item, or the licence of a session that has ended: 401, and the provider is never asked. Test: Task 1, `the cast link serves only its own DRM session, and not after Stop`.
3. **The TV's segment requests carry `?cast=`:** the provider gets the segment's own query without the `cast` parameter. Test: Task 1, `the provider never sees the cast link`.
4. **The Chromecast receiver's licence POST is cross-origin** (an `OPTIONS` preflight, an `Origin` that isn't Atomix's). It is answered, with CORS, for that link only. Test: Task 1, `the TV's licence request: preflight and POST from the receiver's origin`.
5. **A phone that opens Cast to… for an encrypted channel with only a DLNA TV around** sees the "need a Chromecast" sentence, not a DLNA row that fails. Test: Task 2, `v027-ui cast` "only DLNA: the sentence".

**Interfaces:**
- Produces:
  - `links.issue({ drmSessionId, userId, profileId, castId })`; `links.check(token, { route: 'drm', sessionId })`.
  - `rewriteManifest(..., { cast: { base, token } })`:
    - every address is `${base}/api/live/drm/<sid>/r/<n><path>?<query>&cast=<token>`, the clock `${base}/api/live/drm/<sid>/time?cast=<token>`;
    - inside each kept Widevine/ClearKey `ContentProtection` sits `<dashif:Laurl>${base}/api/live/drm/<sid>/licence?cast=<token></dashif:Laurl>`, with the `dashif` namespace declared on the MPD.
  - `LiveDrm.start(..., { castId = null })`: a session with `castId` isn't reaped while its cast is alive (the cast manager calls `drm.touch(id)` on its keep-alive tick).
  - The refusal sentence `DLNA_ENCRYPTED = "This TV can't play encrypted channels; use a Chromecast or Google TV"`.

- [ ] **Step 1: Write the failing tests** (`test/cast-drm.test.js`)

Each of these is a test:
- **"casting an encrypted channel to a Chromecast loads Atomix's DASH manifest as LIVE with the channel's name":**
  - `lastLoad(cc).media.contentType === 'application/dash+xml'`, `streamType === 'LIVE'`, `metadata.title === 'Five'`;
  - `contentId` matches `^${base}/api/live/drm/[0-9a-f]+/manifest\.mpd\?cast=`.
- **"the TV's manifest carries the licence address and absolute segment addresses with the link, and no provider host":**
  - fetch the `contentId` with no cookie. It has `<dashif:Laurl` with `/licence?cast=`;
  - every `media`/`initialization` is absolute on `base` with `cast=`;
  - no `127.0.0.1:<provider port>`, `hdrsecret` or `mansecret`.
- **"the TV's licence request: preflight and POST from the receiver's origin":**
  - `OPTIONS` with `Origin: https://www.gstatic.com` → 204 with `access-control-allow-origin: *`, and `access-control-allow-methods` includes POST;
  - POST a ClearKey JSON request (`{ kids: [b64u(KID)], type: 'temporary' }`) with that Origin → 200, and the JWK has the key.
- **"the provider never sees the cast link":** GET one segment address from the TV manifest. The provider's recorded URL has its own query and no `cast=`.
- **"the cast link serves only its own DRM session, and not after Stop":**
  - the link on another DRM session's manifest → 401;
  - on `/api/items/1/file` → 401;
  - after `cmd(stop)`, the manifest and licence → 401;
  - the DRM session is gone (`nf.app.core.live.drm.sessions.size === 0`).
- **"a DRM cast is kept alive with no browser pings":** advance the session's `lastSeen` 3 minutes back, run the cast keep-alive and `drm.reap()`, and the session is still there.
- **"zapping on the TV between an encrypted and a plain channel on a 1-stream provider leaves one stream":** with `LIVE_TEST_MAX=1`, `channelUp` from Five → Six → (plain) and back. After each: one DRM or playback session for the account, and the cast carries on.
- **"DLNA refuses an encrypted channel with the sentence":** `POST /api/cast/sessions` with the DLNA device → 400 `DLNA_ENCRYPTED`. A FairPlay channel to a Chromecast → 400 "This channel is encrypted, so it can't be cast".
- **"a Kids profile can't cast an encrypted channel outside its groups":** 404, as with plain channels.

- [ ] **Step 3: Implement**

- **`api/cast.js`:** `liveTarget` looks at the device kind (`devices().get(deviceId)`):
  - DLNA plus drm → `DLNA_ENCRYPTED`;
  - `fairplay` → the existing sentence;
  - Chromecast plus widevine/clearkey → allowed;

- **`sessions.js` `playLive`,** when `channel.drm`:
  - `core.live.drm.start({ user, profile, channel, source: plugins.getLiveSource(channel.source), replaces: s.drmSessionId || s.playbackSessionId, isAdmin, clientIp: 'cast', castId: s.id })`;
  - `token = links.issue({ drmSessionId, ... })`;
  - `driver.load({ url: `${s.base}/api/live/drm/${sid}/manifest.mpd?cast=${token}`, contentType: 'application/dash+xml', live: true, kind: 'movie', title, image: channel logo as an absolute cast-image URL or none })`;
  - after the load, stop the old DRM or playback session. On a failed load, stop the new one.
- **`end()`** stops `s.drmSessionId` and revokes the cast's links. The keep-alive interval calls `drm.touch(s.drmSessionId)`.
- **`drm.js`:**
  - `serveManifest` with `ctx.castLink` rewrites with `{ cast: { base: castBase(ctx), token } }`, where `castBase` is the request's own origin (`http://<host>`, as the TV reached it);
  - `serveSegment` deletes `cast` from the forwarded search;
  - `serveTime` with a cast is unchanged apart from the link check.
- **`app.js`:** the same-origin check is skipped when `route.cast && url.searchParams.get('cast')` and the link checks out. `OPTIONS` on a `cast` route answers 204 with `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET, POST, OPTIONS` and `Access-Control-Allow-Headers: content-type`.
