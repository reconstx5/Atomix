# Atomix v0.26.0 Plan B: the three pilot screens and the release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Live TV, every library page, and Search (with its genre and person pages) become Preact `Screen` components that look and behave exactly as in v0.25.0. Then v0.26.0 ships.

**Architecture:**
- Each pilot view module exports `load(params, query)` (which fetches the data first) and `Screen`.
- The pieces that belong to one screen live in `public/js/ui/` (`live.js`, `az-rail.js`) or in the view's own sibling files.
- Code that unconverted screens still call stays as `h()` helpers, moved out of the converted view.
- DOM built by engines (the music `trackList`, `lists.js`'s `collectionCard`) goes in through an `Island` block.
- A frozen copy of v0.25.0 serves as the "before" for the markup, speed and picture checks.

**Tech Stack:** Preact 11.0.1 and htm 3.1.1 through `public/js/ui.js`; Node's test runner; Playwright checks in `/home/claude/devtools`.

**Spec:** `docs/superpowers/specs/2026-10-22-atomix-v026-preact-foundation-design.md` (§2, Verification). Plan A: `docs/superpowers/plans/2026-10-22-atomix-v026-a.md` and its ledger `scratchpad/note/v0260-progress-a.md` (its 9 rulings stand).

## Where this plan departs from the spec

1. **The live-page helpers used by unconverted screens stay as `h()` code in a new `public/js/live-bits.js`:** `channelLogo`, `lockBadge`, `rowName`, `recDot` (Guide, Recordings and the player use them). Only `views/live.js` drops its hand-built DOM.
2. **Network check:** the spec says only "the three vendor files" may be added to a page load. Plan A ruled there are four. Atomix's own new modules (`screen.js`, `state-events.js`, `ui.js`, `ui/*.js`, the split view files) are added too. The check allows exactly those, nothing from another host, and no other library.
3. **The Orbit library bar's hidden `<span hidden>` holding the Collections and Scan buttons goes away.** "…" calls the same functions directly. It was never visible; the markup check lists it as the one expected difference.
4. **The router passes the view element to a Screen as `view`.** Live TV and the library toggle `live-view`, `has-spot`, `is-compact` and `spot-hidden` on it, as today. The alternative was a wrapper element, which would change the markup the CSS selects on.

## Global Constraints

- **"No npm install, no build step."** Only Preact and htm, in `public/js/vendor/`. No new library.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match".
- **No new features this round:** the pilot screens keep every behaviour, sentence and accessible name.
- **Unchanged:** `nav.js`, the CSS and theme classes, the server and its API, the pure rule files (`live-rules.js`, `library-rules.js`, `orbit-rules.js`), the engines and the Kids rules.
- **Rules for Screens:**
  - Data comes in through `load()`, so the router announces, focuses and scrolls only once the page is drawn.
  - Global listeners and classes on elements outside the Screen go in `useLayoutEffect`, so their cleanup runs as the page is left (Plan A deferred minor).
  - List items are keyed by id.
- A check written for old markup gets a ledgered ruling, with no change in what it checks.
- Never `pkill -f`; kill by PID. Run browser suites one after another, never in parallel.
- **No git in the cloud copy:** each "Record" step appends to the ledger.
- Commit on the PC only if Dallas asks. Hash PC files against `cloud.sha` before overwriting them.

## Review Focus

1. **An answer that lands after the page was left:** Live TV's timer or chip reload, a library reload, a search or suggestion answer. It draws nothing, logs no error and leaves the next page alone. Test: Task 5, `late answers after leaving change nothing`.
2. **Answers arriving out of order** (typing fast in the library filter or the search box): only the latest one shows. Test: Task 3, `a slow earlier filter answer doesn't replace a newer one`; Task 4, `a slow earlier search doesn't replace a newer one`.
3. **A focused button that disappears:**
   - Live spotlight's Record when the programme can't be recorded, and Guide with no guide data: focus goes to Watch live.
   - Library Clear filters: focus goes to the first poster.
   - Search, removing a recent search: focus goes to the next ✕, else Clear, else the box.

   Test: Task 2, `a hidden Record hands focus to Watch live`; the existing v025 libfix and v024 search checks cover the other two.
4. **The Kids profile (Mia):** no Recordings link and no Record on Live TV, and the library has no Scan. Test: Task 1's markup snapshots include Mia's Live TV and Movies pages.
5. **Older themes' Live TV row "…" → favourite:** focus comes back to that row's button, and the toast is spoken. Test: Task 2, `an older theme's favourite from "…" returns focus to its row`.
