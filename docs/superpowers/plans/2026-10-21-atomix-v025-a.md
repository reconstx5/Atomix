# Atomix v0.25.0 Plan A — Orbit's Live TV screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Orbit, the Live TV page becomes a spotlight for the channel the remote is on, with a wall of glass channel cards below that show what's on now and next.

**Architecture:**
- **Pure rules:** a new `public/js/live-rules.js` (tested in Node) holds the text, timing and colour rules.
- **Spotlight:** a new `public/js/live-spot.js` builds it and updates it in place, so focus is never lost. It sets the page backdrop through `setBackdrop()`.
- **The page:** `public/js/views/live.js` keeps today's rows for older themes and builds cards when `isOrbit()`.
- **Styling:** layout goes in `public/css/orbit.css` and the look in `themes/orbit/theme.css`, modelled on Home's spotlight and scrolling rows.
- **No server changes:** `/api/live/channels` already sends `now`/`next` with `image`, `description`, times and recording marks.

**Tech Stack:** plain ES modules, CSS, `node:test`, Playwright devtools (outside the repo). No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-21-atomix-v025-orbit-livetv-library-design.md` (§1).

## Global Constraints

- Plain ES-module browser JS with no build step; **no dependencies**.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match". Every change is Orbit-only (`isOrbit()` in JS; `body[data-layout="orbit"]` in `orbit.css`; `themes/orbit/theme.css`).
- Kids profiles keep their rules: no Record, their channel groups only.
- Every control works with a remote (D-pad, Select, Back), a mouse, touch and a screen reader. Text and focus keep the contrast Orbit's checks already measure.
- Cards are four across at TV widths, three on laptops, and two on phones and upright tablets. Card pictures load lazily at their shown size; off-screen cards use `content-visibility: auto`; the page never scrolls sideways.
- Unchanged: the Guide and Recordings pages, the player, now/next moving on at the earliest programme end (and each minute for the bars), favourites, Kids groups, zap order, typed channel numbers, Back, and the empty state when Live TV isn't set up.
- The cloud copy has no git: each "Commit" step is a ledger line. Never `pkill -f`; kill by PID.

## Review Focus

1. **A programme ends while the remote is on its card.** The page reloads now/next (today's timer). The spotlight and the focused card move on to the next programme, and focus stays on the same channel's card. Test: Task 3, check `when a programme ends, the spotlight moves on and focus stays on the channel`.
2. **A programme or logo picture that fails to load** (a 404, a dead guide host). The card falls back to the logo on its tint, or to initials on the tint; no broken-image icon, no blank black card. Test: Task 2, check `a picture that fails to load falls back to the logo on its tint`.
3. **A long channel or programme name** ("Sky Sport Select: Premier League Live — Arsenal v Spurs"). It ellipsises on the card and wraps to two lines at most in the spotlight, never widening the page. Test: Task 2, check `long names ellipsise and the page never scrolls sideways`.
4. **Pressing Record from the spotlight on a channel with no guide, or as a Kids profile.** Record isn't offered then. On a programme already marked, the button reads Recording (or Recording scheduled) and opens the programme sheet, which has Cancel and Stop. Test: Task 3, checks `Kids and no-guide channels offer no Record` and `a recorded programme's button opens its sheet`.
5. **Switching group chips with the remote while the spotlight shows a channel outside the new group.** The spotlight moves to the new group's first channel; it never shows a channel that isn't listed. Test: Task 3, check `a group change moves the spotlight to a listed channel`.

### Task 1: The pure Live TV rules

**Files:**
- Create: `public/js/live-rules.js`.
- Test: new `test/live-rules.test.js`.

**Interfaces:**
- Produces:
  - `channelTint(name: string) → string`: an `hsl(H 45% 32%)` colour. H is a stable hash of the name (FNV-1a, mod 360), so the same name always gets the same colour; an empty name gives `hsl(220 20% 24%)`.
  - `minutesLeft(p: {start, end}, now: number) → string`: "38 min left"; "1 h 5 min left" from 60 minutes; "Ending now" under 1 minute; `''` for no programme.
  - `nextLine(next: {start, title} | null, clock: (ms) → string) → string`: "Next 2:00 PM · Coast", or `''`.
  - `spotStart(channels: {id, favourite}[]) → id | null`: the first favourite, else the first channel, else null.
  - `spotKeep(channels, currentId) → id | null`: `currentId` when it is still listed, else `spotStart(channels)`.

- [ ] **Step 1: Write the failing tests** (`test/live-rules.test.js`):

```js
test('a channel keeps its colour; different names differ', () => {
  assert.equal(channelTint('TVNZ 1'), channelTint('TVNZ 1'));
  assert.notEqual(channelTint('TVNZ 1'), channelTint('Three'));
  assert.match(channelTint('Three'), /^hsl\(\d{1,3} 45% 32%\)$/);
  assert.equal(channelTint(''), 'hsl(220 20% 24%)');
});
test('time left reads in minutes, then hours', () => {
  const at = 1_000_000;
  assert.equal(minutesLeft({ start: at - 60_000, end: at + 38 * 60_000 }, at), '38 min left');
  assert.equal(minutesLeft({ start: at, end: at + 65 * 60_000 }, at), '1 h 5 min left');
  assert.equal(minutesLeft({ start: at, end: at + 20_000 }, at), 'Ending now');
  assert.equal(minutesLeft(null, at), '');
});
test("the card's next line", () => {
  assert.equal(nextLine({ start: 1, title: 'Coast' }, () => '2:00 PM'), 'Next 2:00 PM · Coast');
  assert.equal(nextLine(null, () => 'x'), '');
});
test('the spotlight starts on the first favourite and keeps a listed channel', () => {
  const list = [{ id: 1 }, { id: 2, favourite: true }, { id: 3 }];
  assert.equal(spotStart(list), 2);
  assert.equal(spotStart([{ id: 5 }]), 5);
  assert.equal(spotStart([]), null);
  assert.equal(spotKeep(list, 3), 3);
  assert.equal(spotKeep(list, 9), 2, 'a channel no longer listed gives way to the start');
});
```

**Interfaces:**

- Produces: `liveSpotlight({ onWatch(c), onRecord(c), onFavourite(c), onGuide(c), onCast(c) }) → { el: HTMLElement, show(c, now = Date.now()): void }`.
  - **`el`:** a `section.live-spot[aria-label="Spotlight"]` holding:
    - `.live-spot-top`: the logo, `span.live-tag` "LIVE", and "Channel N · <first group>";
    - `h2.live-spot-title` (the programme title, or the channel name when there's no guide);
    - `.live-spot-time`: the start time, a bar, and `minutesLeft`;
    - `p.live-spot-desc` (two lines at most);
    - `.live-spot-actions` with buttons in this order:
      - Watch live;
      - Record, Recording or Recording scheduled;
      - ★ Favourite (`aria-pressed`);
      - Guide;
      - Cast to….
  - **`show(c)`:** updates the text and buttons in place (no replaced button holds focus), hides Record for Kids or a channel with no guide, and hides Cast for radio, encrypted channels or when casting is off.
  - **Backdrop:** `show(c)` calls `setBackdrop(c.now?.image || null)`. With no picture, it sets `--tint` on `.live-view` for the backdrop wash.
  - **Record, when the programme isn't marked:** `recordProgramme(now.id)`, then a toast "Recording <title>" (or "Recording scheduled") and a reload with focus kept.
  - **Record, when marked:** opens `openProgramme(now.id)`.
