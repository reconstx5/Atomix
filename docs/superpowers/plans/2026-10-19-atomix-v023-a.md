# Atomix Round 25 — Plan A (core extensions for the new plugins) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give plugins what Plans B and C need: outside scores stored and shown, metadata for books and audiobooks, ids passed between providers, four viewer-filtered library helpers, and server-problem events.

**Architecture:** Small extensions where each concern already lives — `metadata.js` (fields, merge, write), `editing.js` (lock/clear), `serialize.js` + `components.js metaLine` (show), `queries.js` (helpers, exposed through `plugins.js` `api.library`), and one new `src/problems.js` that turns "it broke / it's fine again" calls into `server:problem` / `server:recovered` events once per key.

**Tech Stack:** Node ≥ 22.13 (`node:test`, `node:sqlite`, `fs.statfsSync`); plain ES-module browser JS; Playwright devtools.

**Spec:** `docs/superpowers/specs/2026-10-19-atomix-v023-plugins-design.md` section 1.

## Global Constraints

- No dependencies; no Kodi GPL code; keys and tokens never reach the browser or the logs.
- Kids profiles never see a title outside their rules — every helper takes a viewer and filters with the existing `visibility`/`canSee` rules.
- Older themes pixel-identical (`node devtools/oldthemes-compare.mjs compare` → "all pages match").
- Plugins only fill gaps; locked fields stay locked; for `book` / `audiobook` the file's own title and author always win.
- Copy (exact): the meta line "IMDb 7.8 · Rotten Tomatoes 93% · Metacritic 81"; Edit details button "Clear scores"; problem sentences below.
- Every item: a test that fails first; unit suite green at each task's end.

## Review Focus

1. **A provider that returns scores in a wrong shape** (a string, an object, a value with no source) — ignored, never stored as junk or shown as "undefined" (Task 1 test).
2. **A book whose EPUB has a title and description, and a plugin that returns other ones** — the book's own stay; only empty fields fill (Task 2 test).
3. **A Kids profile and the row helpers** — an R16 show part-watched by its parent never comes back for the Kids profile; a film series with an R16 part offers only allowed parts (Task 3 tests).
4. **A problem that keeps happening** (a folder missing at every scan, a feed failing every check) — one `server:problem` until it clears, not one per scan (Task 4 test).
5. **A disk check on a folder that doesn't exist yet** (recordings never made) — no crash, no false "under 5 GB" (Task 4 test).

### Task 3: Library helpers for rows

**Files:** Modify `src/library/queries.js` (`list({ keyword })`; `startedShows`, `partlySeenSeries`, `playedOn`), `src/plugins.js` (`api.library` exposes them). Test: `test/library-helpers.test.js` (new).

**Interfaces — Produces** (all on `core.library` and `api.library`; rows are DB rows, filtered for `viewer` like `list()`):
- `list({ viewer, keyword })` — `EXISTS (SELECT 1 FROM json_each(i.keywords) k WHERE k.value = lower(?))`.
- `startedShows(viewer, { idleDays = 14, limit = 20 }) → [{ show, next, left, lastWatchedAt }]` — shows with ≥ 1 watched and ≥ 1 unwatched episode (watched = progress.watched for this profile), last progress update older than `idleDays`; `next` the first unwatched episode by season/episode (seasons > 0 before specials); `left` the unwatched count; newest `lastWatchedAt` first.
- `partlySeenSeries(viewer, { limit = 20 }) → [{ collection: { id, name, poster }, next, seen, total }]` — collections (not hidden) with ≥ 1 watched film and ≥ 1 unwatched film among the viewer's allowed members; `next` the first unwatched member by `collection_items.position`; `total` the allowed members in the library.
- `playedOn(viewer, date: 'YYYY-MM-DD', { tz })` → items this profile has a counted play for on that local day (zone from `tz`, IANA, default the server's), newest first, one per item.

- [ ] **Step 1: Failing tests** (a test DB like `test/home-api.test.js` builds, with a grown-up and a Kids profile maxAge 10)
  - `keyword finds titles by their TMDB keywords` ('Christmas' finds a film with `["christmas","snow"]`; not one with `["christmas eve"]`).
  - `startedShows lists stalled shows with their next episode` (S1E1 watched 20 days ago, S1E2 unwatched → `{ next: S1E2, left: 1 }`; a show watched 3 days ago → absent with idleDays 14, present with 0; a fully watched show absent).
  - `startedShows never offers a Kids profile a show outside its rules` (an R16 show the Kids profile watched once before the rating changed → absent).
  - `partlySeenSeries offers the next unseen part` (3 parts, part 1 watched → next part 2, seen 1, total 3; an R16 part 2 for the Kids profile → next part 3, total 2).
  - `playedOn gives what this profile played that day` (two plays on 2025-10-19 in `Pacific/Auckland`, one on 2025-10-20 → the two; another profile's play absent).
  - `api.library has the helpers` (a fixture plugin calls each through `api.library` from a route; 200 with arrays).

### Task 4: Server-problem events

**Files:** Create `src/problems.js`; modify `src/app.js` (`core.problems = new Problems({ hooks: core.hooks })`, passed to the scanner, remote sync, podcasts, live refresher; the hourly disk watch started with the server, stopped on `app.stop`), `src/library/scanner.js` (missing folder :233, looks-empty :226 → `report`; a root read fine → `clear`), `src/remote/sync.js` (ping failure :47 → `report('remote-server', server.id, …)`; a good sync → `clear`), `src/podcasts/index.js` (failures reaching 3 → `report('podcast-feed', feed.id, …)`; success → `clear`), `src/live/refresh.js` (failure → `report('live-source', key, …)`; ok → `clear`). Test: `test/problems.test.js` (new), `test/passover-library.test.js`, `test/remote-sync.test.js`, `test/podcasts.test.js`, `test/live-refresh.test.js`.

**Interfaces — Produces:** `class Problems { constructor({ hooks, now }); report(kind, key, text): boolean (true when newly raised); clear(kind, key): boolean; list(): [{ kind, key, text, since }] }` — emits `server:problem { kind, key, text }` on a new key, `server:recovered { kind, key }` when a raised key clears; nothing for repeats. `startDiskWatch({ problems, dirs: () => [{ key, label, dir }], freeBytes, everyMs = 3_600_000 }) → stop()` in `src/problems.js`: a dir that doesn't exist is checked at its nearest existing parent; under `5 * 1024 ** 3` bytes → report `disk`, else clear.

Sentences (exact; folder paths as configured, never addresses with credentials):
- `library-folder`: "The <library> folder <path> is missing." / "The <library> folder <path> looks empty, so its titles were kept."
- `remote-server`: "<server> isn't answering (<detail>)." — detail as `setStatus` has it, already token-free.
- `podcast-feed`: "The feed for <show> has failed 3 checks in a row."
- `live-source`: "The Live TV source <name> couldn't refresh (<error>)."
- `disk`: "Only <n> GB free for <label> (<path>)." — labels "Atomix's data", "recordings", "downloads".

- [ ] **Step 1: Failing tests**
  - problems.test: `a problem is announced once and its recovery once` (report ×3 → one `server:problem`; clear → one `server:recovered`; clear again → nothing; report again → a new problem).
  - problems.test: `the disk watch reports under 5 GB and clears above` (injected freeBytes 4 GB → `disk` problem with "Only 4 GB free for recordings (…)", 6 GB → recovered; a dir that doesn't exist uses its parent, no throw).
  - passover-library: `a folder that looks empty raises one problem across two scans`; `a missing library folder raises a problem, and finding it again clears it`.
  - remote-sync: `an unreachable server raises a problem and a good sync clears it` (the payload text contains no token).
  - podcasts: `a feed failing its third check raises a problem; a good check clears it` (no event at the 1st or 2nd failure).
  - live-refresh: `a source whose refresh fails raises a problem; the next good refresh clears it`.
- [ ] **Step 2: Run → FAIL**; **Step 3: Implement**; **Step 4: Run → PASS**, then the four touched test files and `test/live-scheduler.test.js`.
