# Atomix v0.24.0 Plan C — Search that helps, and the release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search ignores accents, case, punctuation and a leading "the" everywhere. Orbit's search page helps before and during typing: recent searches, genre and library tiles, suggestions from the first letter, and person and genre pages. Then v0.24.0 is released.

**Architecture:**
- **Matching.** A new `src/library/searchkey.js` owns normalisation (pure functions, tested in Node).
  - It registers a deterministic SQL function `atomix_key(text)` on the app's connection.
  - Each item stores `items.search_key` (migration 29). The column starts NULL. A pure-SQL trigger resets it to NULL when a title changes.
  - `ensureSearchKeys(db)` fills every NULL key just before a search runs, using a partial index. So every write path, and the devtools' raw database writes, need no change.
  - Every search (the full results, the music apps, the new suggestions) matches on the key.
- **New routes.** A new `src/api/search.js` holds:
  - recent searches (migration 29's `search_history`);
  - suggestions;
  - the before-typing tiles;
  - the genre and person pages' data.
- **The page.** `public/js/views/search.js` gains an Orbit-only before-typing panel and a suggestion list. New `views/genre.js` and `views/person.js` show the genre and person pages. Older themes keep their search page as it is.

**Tech Stack:** Node ≥ 22.13 (`DatabaseSync#function`, added in 22.13), `node:sqlite`, `node:test`, plain ES modules, Playwright devtools (outside the repo). No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-atomix-v024-ui-design.md` (§3, and the Verification section for the release).

## Global Constraints

- Node ≥ 22.13, `node:sqlite`; plain ES-module browser JS with no build step; **no dependencies**.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match". Their search page keeps its look; only the matching improves.
- Kids profiles never see admin data, nor any title outside their rules (age rating, allow-unrated, libraries). This covers suggestions, people, person pages, genres, genre pages, library tiles and recent searches. A person whose only titles the Kids profile can't see is never suggested to it. Every query goes through `library.visibility(viewer)`.
- **Recent searches:** at most 10 per profile, newest first, with exact repeats (trimmed, case-insensitive) moved to the top. A search is remembered on Enter or on opening a result. Deleting a profile deletes its list.
- **Suggestions:**
  - Up to 8 entries `{ kind, id?, title, subtitle, poster? }` across films, shows, artists, albums, podcasts, audiobooks, books, comics and people, from the first letter.
  - Ranking: prefix → word-prefix → contains, then shorter titles first.
  - Debounced about 150 ms, and abandoned when typing continues.
  - Down from the box enters them; Select opens one; Back returns to the box.
- **Tiles:** up to 12 genre tiles (genres of films and shows this viewer can see, most common first) and one tile per library the viewer can see.
- **Matching:** "amelie" finds *Amélie*; "spiderman" finds *Spider-Man*. It is keyed on title and original title.
- Every new control works with a remote (D-pad, Select, Back), a mouse, touch and a screen reader.
- The cloud copy has no git: each "Commit" step is a ledger line. Never `pkill -f`; kill by PID.

**Interfaces:**
- Produces (in `searchkey.js`):
  - `searchWords(text: string) → string`:
    1. NFKD;
    2. remove combining marks (`\p{M}`);
    3. lower-case;
    4. drop apostrophes (`'` and `’`);
    5. turn every other run of non-letter, non-digit characters into one space;
    6. trim.
  - `searchKey(text) → string`: `searchWords` with the spaces removed.
  - `queryKeys(q: string) → string[]`: the distinct non-empty keys of `q`, and of `q` without a leading "the " (case-insensitive). Empty when `q` normalises to nothing.
  - `rankTitle(title: string, q: string) → 0 | 1 | 2 | 3`:
    - 0 = the title's key starts with a query key;
    - 1 = a word of the title starts it (that word's key and every word after it, joined, start with the key);
    - 2 = contains;
    - 3 = no match.
    - Both sides are compared with and without a leading "the".
  - `registerSearchKey(db)`: `db.function('atomix_key', { deterministic: true }, (s) => (s == null ? null : searchKey(String(s))))`.
  - `ensureSearchKeys(db)`: `UPDATE items SET search_key = atomix_key(title) || '|' || COALESCE(atomix_key(original_title), '') WHERE search_key IS NULL`.
  - `keyMatch(column: string, q: string) → { sql: string, params: string[] }`: `(column LIKE ? OR column LIKE ?)`, one `%key%` per query key. When there are no keys it returns `{ sql: '0', params: [] }`.
- Migration 29 (with Task 2's table, one migration):

```sql
ALTER TABLE items ADD COLUMN search_key TEXT;
CREATE INDEX items_search_key_missing ON items(id) WHERE search_key IS NULL;
CREATE TRIGGER items_search_key_reset AFTER UPDATE OF title, original_title ON items
  BEGIN UPDATE items SET search_key = NULL WHERE id = NEW.id; END;
CREATE TABLE search_history (
  id INTEGER PRIMARY KEY,
  profile_id INTEGER NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  query TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX search_history_profile ON search_history(profile_id, created_at DESC);
```
