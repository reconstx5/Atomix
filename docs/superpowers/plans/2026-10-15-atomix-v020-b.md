# Atomix Round 22 — Plan B (music apps over the Subsonic API, and scrobbling) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phone music apps (Amperfy, Symfonium, play:Sub, Feishin…) sign in to Atomix with an app password and browse, stream, star, rate, scrobble and edit playlists; each profile can send what it listens to to ListenBrainz and Last.fm.

**Architecture:** A separate handler at `/rest/` (`src/subsonic/`) — not the JSON `/api/` router: Subsonic answers HTTP 200 with its own envelope in XML, JSON or JSONP, takes query or form parameters, and signs in with an app password per request. It resolves the app password to a user + profile and builds the same `viewer` the web uses, so every method goes through `Library.visibility(viewer)`. It reuses Plan A: `Plays` (history), `UserRatings` (stars/favourite), `Lists` + `smartRows` (playlists). Scrobbling (`src/scrobble/`) listens to `Plays.onStarted`/`onCounted` for songs and sends to each profile's services through a retrying queue.

**Tech Stack:** Node ≥ 22.13, `node:sqlite`, `node:crypto` (md5, timingSafeEqual, randomBytes), ffmpeg; plain ES-module browser JS; `node:test`; Playwright devtools.

**Spec:** `docs/superpowers/specs/2026-10-15-atomix-v020-design.md` (sections 2 and 3; Migrations 20). Builds on Plan A (`docs/superpowers/plans/2026-10-15-atomix-v020-a.md`).

## Global Constraints

- No dependencies. Node ≥ 22.13, `node:sqlite`, ffmpeg; plain ES-module browser code.
- App passwords: random 24 characters, kept (token sign-in needs them), shown once; list shows last used; Revoke; limit 20 per profile.
- `/rest/<method>` and `/rest/<method>.view`, GET and POST (form body), `f=xml|json|jsonp`, API version `1.16.1`, `openSubsonic: true`, extensions `songLyrics`, `apiKeyAuthentication`, `formPost`, `transcodeOffset`.
- Auth: `u` + (`t` = md5(app password + `s`) | `p` = app password or `enc:<hex>`) | `apiKey`. Wrong → error 40; revoked → 40; missing → 10. The profile's library access and Kids rules apply; `adminRole` from the account's role (no admin methods).
- Ids: `ar-<id>`, `al-<id>`, `tr-<id>`, `pl-<id>`, smart lists `sp-<id>` (read-only: updating one → error 50). Unknown methods → error 0 "Not supported in Atomix".
- stream: the original file when no `format`/`maxBitRate` is asked or it already fits; else MP3 (default) or Opus at 32–320 kbps with `timeOffset`; ranges for the original; counts toward the transcode cap.
- Secrets never reach the browser or the logs: app passwords shown once; Last.fm session keys, ListenBrainz tokens and the Last.fm API secret stay server-side. Server file paths never appear in Subsonic answers.
- Scrobbling: songs only; "now playing" at a song's start; a scrobble when counted; failures (network, 5xx) queued and retried with backoff for 14 days; 401/invalid session stops that service for the profile ("Connect again"); the card shows last sent and last error.
- Older themes stay pixel-identical (`oldthemes-compare.mjs compare` → "all pages match"). TV-remote friendly settings cards; no browser dialogs.

## Review Focus

1. **A wrong password ten times from a music app** — the same sign-in lockout as the web (error 40 with the "Too many sign-in attempts" sentence), and no lockout for the right password from another address (Task 1 test `music apps share the sign-in lockout`).
2. **A Kids profile's app password** — every list, search, random pick, star list, playlist and stream obeys the kid's rules; an R-rated album's songs are invisible and 70 on direct ids (Task 2 test `a Kids app password sees only what the kid may`, Task 3 test `stream refuses what the profile can't see`).
3. **A client that asks `maxBitRate=128` for a 96 kbps MP3, or `format=raw`** — the original bytes with ranges, no conversion (Task 3 test `stream sends the original when it already fits`).
4. **Last.fm or ListenBrainz down for a day, then back** — the queued listens go out in order with their original times, once each, and a 401 stops retrying (Task 5 tests `queued listens go out once, in order` and `a refused token stops the service`).
5. **A revoked app password still cached by a client with token auth** — refused on the very next call (Task 1 test `revoked passwords stop at once`).

### Task 5: Scrobbling to ListenBrainz and Last.fm

**Files:**
- Create: `src/scrobble/index.js` (`Scrobblers`), `src/scrobble/listenbrainz.js`, `src/scrobble/lastfm.js`, `src/api/scrobble.js`
- Modify: `src/config.js` (`listenbrainzBase` ← `ATOMIX_LISTENBRAINZ_BASE` default `https://api.listenbrainz.org`, `lastfmBase` ← `ATOMIX_LASTFM_BASE` default `https://ws.audioscrobbler.com/2.0/`, `lastfmAuthBase` ← `ATOMIX_LASTFM_AUTH_BASE` default `https://www.last.fm/api/auth/`), `src/settings.js` (`lastfmApiKey`, `lastfmSecret`), `src/api/admin.js` (`SECRET_SETTINGS` gains `lastfmSecret`), `src/app.js`
- Test: `test/scrobble.test.js` (fake services with `fakeServer`)

**Interfaces:**
- Consumes: `Plays.onStarted` / `onCounted` (songs only), migration 20 tables.
- Produces: `class Scrobblers { constructor({ db, settings, config, now, fetchFn, log }); status(profileId) → [{ service, connected, username, lastOk, lastError, stopped }]; connectListenBrainz(profileId, token) → status row (checks `GET <base>/1/validate-token` with `Authorization: Token <t>`; invalid → HttpError(400, "ListenBrainz didn't accept that token.")); lastfmStart(profileId, callbackUrl) → { url } (state nonce kept 10 min, bound to the profile); lastfmFinish(profileId, { token, state }) (signed `auth.getSession` → session key + name); disconnect(profileId, service); nowPlaying(event); listen(event); drain() → Promise (sends due queue rows; started every 60 s and after each enqueue) }`.
- Payloads: ListenBrainz `POST <base>/1/submit-listens` `{ listen_type: 'playing_now'|'single', payload: [{ listened_at (s, single only), track_metadata: { artist_name, track_name, release_name, additional_info: { duration_ms, tracknumber, submission_client: 'Atomix', submission_client_version } } }] }`. Last.fm `POST <base>` form `method=track.updateNowPlaying|track.scrobble, artist, track, album, duration, trackNumber, timestamp (scrobble), api_key, sk, api_sig, format=json` with `api_sig` = md5 of the sorted `key+value` pairs (excluding `format`, `callback`) + secret.
- Queue rules: a listen is written to `scrobble_queue` before sending; sent → row deleted, `last_ok` set; network error / 5xx / 429 → `tries+1`, `next_at = now + min(2^tries minutes, 6 h)`; older than 14 days → dropped; 401/403 (ListenBrainz) or Last.fm error 9 (invalid session) / 4 / 26 → `stopped = 1`, `last_error = "Connect again"`, that service's queue rows for the profile dropped. "Now playing" is never queued (dropped on failure). Queue rows go out oldest first, one service at a time.
