# Atomix Round 23 — Plan C (tidy-up: Live TV recording and rewind, music apps, smart playlists) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the v0.19 and v0.20 review leftovers for Live TV (tuners, rewind, recording, the Recordings page), the music apps' API and smart playlists/ratings, each with a test that fails first.

**Architecture:** No new subsystems. Each item is a small change in the file that owns it; one test per item (Node test where the behaviour is server-side, a `devtools/v021-ui.mjs` check where it is a page). Migration 23 (unreleased, edited in place) gains `live_recordings.work_dir`.

**Tech Stack:** Node ≥ 22.13 (`node:test`, `node:sqlite`), ffmpeg; plain ES-module browser JS; Playwright devtools.

**Spec:** `docs/superpowers/specs/2026-10-16-atomix-v021-design.md` section 3 (and Testing, Hard limits). The item list and locations were mapped from the code (v0.20 reviews' deferred minors in `claude/build-status.md`).

## Global Constraints

- Every item: a test that fails first, then the change; the full unit suite green at each task's end.
- Copy (exact): "The provider refused this channel" (a provider 401/403 on a fresh tuner); "Busy converting other songs or videos; try again in a moment."; "Removed"; "Stopped recording <title>" / "Nothing was recorded of <title>"; "Start early and End late need a number of minutes"; "Pick a folder that isn't the Atomix data folder or a drive's top level".
- No provider URL, header or token in a browser answer or a log line (existing redaction stays).
- Older themes pixel-identical (`oldthemes-compare` "all pages match"); `live-ui`, `music-ui`, `v020-ui`, `a11y-ui` stay green.
- No dependencies; no Kodi GPL code.

## Review Focus

1. **A tuner shared by a viewer and a recording, viewers coming and going for hours** — no listener or closure left per departed viewer; the recording carries on (Task 1 test `listeners go with their viewer`).
2. **A provider that refuses (403) or changes its stream URL** — the viewer hears why at once; a long tuner re-asks the source for its address on restart (Task 1 tests `a refused channel says so at once`, `a restart asks for a fresh address`).
3. **Shutdown or a folder change during a recording's join** — the join finishes (≤ 10 s) and the pieces stay findable (Task 2 tests `stop waits for joins`, `the work folder stays with its recording`).
4. **A music app asking for formats/bitrates Atomix didn't expect, or leaving mid-request** — a playable conversion, and no ffmpeg left running (Task 4 tests).
5. **A Kids profile's PATCH that would partly succeed** — nothing saved when any part is refused (Task 5 test `a Kids PATCH saves nothing when refused`).

### Task 2: Recording

- Modify: `src/db.js` (migration 23: `ALTER TABLE live_recordings ADD COLUMN work_dir TEXT`), `src/live/scheduler.js` (`retune`, `workDir`, `stop`, `afterRefresh`, `clashFor`, `finishRec`, `removeRecording`, new `retryJoin(id)`), `src/live/recorder.js` (`safeName`, `DirectRecorder.spawnNext`), `src/live/stream.js` (`takeSlotFor`), `src/app.js` (`stop` awaits the scheduler), `src/api/admin.js` (recordings folder rule), `src/api/recordings.js` (`PATCH /api/live/rules/:id` cancels, `POST /api/live/recordings/:id/retry`)

**Interfaces:**
- Produces: `scheduler.stop() → Promise` (resolves when pending joins settle, at most 10 s); `scheduler.retryJoin(id) → recording`; route `POST /api/live/recordings/:id/retry` (admin or the recording's profile) → the shaped recording; shaped failed recordings gain `canRetry: boolean` (work folder still there).

- [ ] **Step 1: Failing tests**
  - `retune takes a slot and gives up after 3 tries`: a tuner that won't start → `takeSlotFor` called each try, released each time, the recording failed with its reason after the third tick.
  - `DirectRecorder backs off`: respawns at 2, 4, 8 … capped at 60 s (fake timers).
  - `safeName never starts or ends with a dot or space`: ".hack", "Name.", a 130-character name whose cut ends in "." → none start or end with `.`/space.
  - `a viewer start in progress doesn't count as a recording`: one slot reserved by a starting viewer, max 1 → `takeSlotFor` stops that viewer (as for viewers) rather than `EVERY_STREAM_RECORDING`.
  - `stop waits for joins`: a join that takes 2 s in flight → `await scheduler.stop()` resolves after it; a 20 s join → resolves at 10 s.
  - `the recordings folder rule`: PUT `recordingsDir` = the data folder, a folder inside it other than `<data>/recordings`, or `/` → 400 "Pick a folder that isn't the Atomix data folder or a drive's top level"; the default `<data>/recordings` accepted.
  - `the work folder stays with its recording`: start a recording, change `recordingsDir`, finish → the pieces are joined from the recording's own `work_dir`; `recover` after a restart uses it too.
  - `a rule edit cancels airings that no longer match`: rule on channel A with two scheduled airings → PATCH to channel B → both `cancelled`, B's airings scheduled; a new-only edit cancels scheduled repeats.
  - `clashes are counted once per tuner`: three recordings, two on one channel → "overlaps 1 other recording" style count by channel.
  - `a failed join can be tried again`: a join that fails keeps `.work/<id>`; `canRetry: true`; retry → joined, `done`; Remove deletes the work folder too.
  - migrations: `work_dir` exists after 23.
- [ ] **Step 2: Run → FAIL**; **Step 3: Implement**; **Step 4: Run → PASS**, then `node devtools/live-ui.mjs`.
