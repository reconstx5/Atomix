# Atomix v0.23.0 Plan C — Home rows, Alerts and the release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three new Home rows that respect every profile's rules (**Finish what you started**, **Seasonal picks**, **On this day**), the alerts plugin renamed **Alerts** with ntfy, Telegram and Pushover plus server-problem alerts, and the v0.23.0 release (version, README Plugins section, docs, pictures).

**Architecture:**
- A new plugin `more-home-rows` (on by default) builds its rows from database rows only, using the Plan A helpers, so Kids limits and `canSee()` apply as for every row.
- A plugin row can now:
  - give a card a short **note** ("4 episodes left");
  - give the row its own **title** per viewer (the season's name).
- `api.library.list({ releasedOn: 'MM-DD' })` finds films released on a day.
- The `notifications` plugin keeps its id and settings. It gains three channels and listens for Plan A's `server:problem` / `server:recovered`. Its Test button reports each channel.

**Tech Stack:** Node ≥ 22.13, `node:test`, plain ES modules, Playwright devtools (outside the repo). No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-atomix-v023-plugins-design.md` (§3). Plans A and B are complete. Their ledgers are archived at `/tmp/claude-0/-home-claude/8bc10209-2aa9-5a8a-8d5c-99df538b4e2a/scratchpad/note/v0230-progress-{a,b}.md`.

## Global Constraints

- Node ≥ 22.13; plain ES-module browser JS; **no dependencies**; no Kodi GPL code.
- Tokens (Telegram bot token, Pushover app token and user key, ntfy access token) are `password` settings. They never reach the browser or the logs. The Telegram token is part of its URL, so no channel's URL is ever logged; error text is built from status and the service's own message only.
- Kids profiles never see admin data, and never see a title outside their rules in any new row: only database rows are returned, and `rows.js` filters them with `canSee()`.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match". A card without a note looks exactly as before.
- Tests reach fake services only. Telegram's base comes from `ATOMIX_TELEGRAM_BASE`, Pushover's from `ATOMIX_PUSHOVER_BASE`, and ntfy's from its server setting.
- Row keys in Arrange home: `plugin:more-home-rows/finish`, `plugin:more-home-rows/seasonal`, `plugin:more-home-rows/on-this-day`. Each row is hidden when empty.

  - Row titles: "Christmas films", "Halloween frights", "Valentine's picks", "Summer films".

### Task 2: `more-home-rows`

**Files:**

**plugin.json:**
- id `more-home-rows`, name "More Home rows", **enabledByDefault true**.
- description: "Adds Finish what you started, Seasonal picks and On this day to Home. Each row follows every profile's rules and hides when it's empty."
- settings:
  - `idleDays`: number, label "Finish what you started: left for at least (days)", default 14.
  - `hemisphere`: select `southern` / `northern`, label "Seasons", default `southern`. Options "Southern hemisphere (summer in Dec–Feb)" and "Northern hemisphere (summer in Jun–Aug)".

**Interfaces:**
- Consumes:
  - Task 1's notes, `{ title, items }` and `releasedOn`;
  - Plan A's `startedShows`, `partlySeenSeries` (with `part`), `playedOn` and `list({ keyword, genre })`.
- Produces:
  - `export function today()`: `process.env.ATOMIX_TODAY` (`YYYY-MM-DD`, test-only) or the server's local date, as a `{ y, m, d }` object.
  - `export function seasonFor({ m, d }, hemisphere) → string[]`: the candidate seasons, best first.
    - Dec → `['christmas', 'summer']` (southern), or `['christmas']` (northern).
    - Oct → `['halloween']`.
    - 1–14 Feb → `['valentines', 'summer']` (southern), else `['summer']` for Jan / 15–28 Feb (southern).
    - Jun–Aug → `['summer']` (northern).
    - Otherwise `[]`.
  - `export const SEASONS`:
    - christmas: title "Christmas films", keywords christmas, santa claus, christmas eve.
    - halloween: title "Halloween frights", keyword halloween, genre Horror.
    - valentines: title "Valentine's picks", keyword valentine's day, genre Romance.
    - summer: title "Summer films", keywords summer, summer vacation, summer camp, beach.
  - Rows, all films and episodes as database rows:
    - `finish`: "Finish what you started", landscape, position 15.
    - `seasonal`: the season's title, poster, position 45.
    - `on-this-day`: "On this day", poster, position 46.

**Behaviour:**
- **Finish what you started:**
  - Next episodes from `startedShows(viewer, { idleDays })`, with note `` `${left} episodes left` `` (`1 episode left`).
  - Then next films from `partlySeenSeries`, with note `` `Part ${part} of ${total}` ``.
  - It leaves out:
    - any show with an episode in Continue watching (`continueWatching` + `nextUp`, as `rows.js` builds it);
    - any film that is in progress there.
  - Up to 20, ordered by the last watch, newest first.
- **Seasonal picks:**
  - Takes the first candidate season with at least 4 films for this viewer: the union of its keywords and genres, deduplicated, best rated first, up to 20.
  - It returns `{ title, items }`, or `[]` when none qualifies.
- **On this day:**
  - First, what this profile played a year ago today: `playedOn(viewer, <y-1>-MM-DD)` with note "You watched this a year ago". Films and episodes only, each title once.
  - Then films with `releasedOn: 'MM-DD'`, with note `` `Released ${d} ${Mon} ${yyyy}` `` (e.g. "Released 19 Oct 1985").
  - Deduplicated, up to 20.

**Interfaces:**
- Consumes: Plan A's `server:problem { kind, key, text }` and `server:recovered { kind, key }`.
- Produces, from `channels.js`:
  - `sendNtfy(api, cfg, { title, text })`: POST `${server}/${encodeURIComponent(topic)}`. Headers: `Title` (with non-ASCII encoded as RFC 2047), and `Authorization: Bearer` when there's a token.
  - `sendTelegram(api, cfg, { text })`: POST `${ATOMIX_TELEGRAM_BASE || 'https://api.telegram.org'}/bot${token}/sendMessage` with JSON `{ chat_id, text, disable_web_page_preview: true }`.
  - `sendPushover(api, cfg, { title, text })`: POST `${ATOMIX_PUSHOVER_BASE || 'https://api.pushover.net'}/1/messages.json` as a form `{ token, user, title, message }`. The message is cut to 1024 characters.
  - Each resolves on success, or throws an `Error` whose message is the reason people read:
    - Telegram 401: `Unauthorized (check the bot token)`.
    - Telegram 400 with "chat not found": `chat not found (check the chat id)`.
    - ntfy 401/403: `Unauthorized (check the access token)`.
    - Pushover: its `errors[0]`.
    - Otherwise: `answered <status>`, or `no answer` / `timed out`.
    - Every request has a 15 s timeout.
- Produces, in index.js:
  - `export function report(results) → string`: `[{ name, error? }]` in channel order (ntfy, Telegram, Pushover, Discord, Webhook, Email) becomes `"ntfy: sent · Telegram: Unauthorized (check the bot token)"`.
  - With no channel filled in: `Nothing is set up yet. Fill in a channel (ntfy, Telegram, Pushover, Discord, a webhook or email) first.`
  - The Test action returns `{ message: report(...) }`.
  - New-title messages go to every channel as before (when `alertNew` is on), now including the three new ones.

**Problems:**
- When `alertProblems` is on, a `server:problem` sends `⚠ <server name>: <text>` (title `Problem on <server name>`) to every channel.
- It is skipped when the same `kind:key` was sent less than 24 hours ago (storage `sent:<kind>:<key>` = time and text).
- When `alertRecovered` is on, a `server:recovered` for a key that was sent once sends `✓ <server name>: back to normal — <the sent text>`, and is then forgotten (one per sent problem).
