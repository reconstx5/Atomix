# Atomix Round 22 — Plan A (play history, stars and hearts, smart playlists) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Atomix remembers what each profile played and what it thinks of it (plays, stars, favourites), and builds smart playlists from rules over that and the library.

**Architecture:** Migration 19 adds `plays` and `user_ratings` and rebuilds `lists` (kind `smart`, `rules`, `media`). Two small stores — `src/library/plays.js` (writes and counts plays from every progress report) and `src/library/userratings.js` — feed `Library.withProgress`, so every item the API serializes carries the viewer's `playCount`, `lastPlayed`, `stars`, `favourite`. `src/library/smart.js` validates rules and turns them into one SQL query run through `Library.visibility(viewer)`; `Lists` dispatches a smart list's rows to it. Browser: `public/js/rating.js` (the stars-and-heart control) and `public/js/views/smartlist.js` (the builder).

**Tech Stack:** Node ≥ 22.13, `node:sqlite`, `node:test`; plain ES-module browser JS; Playwright devtools in `/home/claude/devtools`.

**Spec:** `docs/superpowers/specs/2026-10-15-atomix-v020-design.md` (sections 0 and 1; Migrations 19).

## Global Constraints

- No dependencies. Node ≥ 22.13, `node:sqlite`, ffmpeg; plain ES-module browser code.
- Kids profiles: their library rules apply to smart playlists; ratings are per profile and any profile (Kids included) may rate.
- A song is **counted** after half its length or 4 minutes (whichever first); a film or episode when it is marked watched. One row per playing (a resumed title updates its open row for 6 hours).
- Ratings: stars 1–5 or null, favourite 0/1, for tracks, albums, artists, films and shows. Route `PUT /api/items/:id/rating {stars|null, favourite}`.
- Smart lists are evaluated each time they're opened or played (never stored), always through the viewer's visibility; a shared smart list is evaluated for the viewer, not its owner. Rule errors are refused on save with a sentence naming the rule.
- Older themes stay pixel-identical: `node devtools/oldthemes-compare.mjs compare` → "all pages match".
- TV-remote friendly: every new control reachable by arrows/Tab/Enter; no browser dialogs.

## Review Focus

1. **A song seeked to its end, or skipped after 10 s** — not counted; only listened time counts (Task 1 test `seeking ahead doesn't count a song`).
2. **A title resumed 5 hours later vs 7 hours later** — same play row vs a new one (Task 1 test `a resume within 6 hours keeps its play`).
3. **A grown-up's shared smart list of R16 films opened by a Kids profile** — the kid sees only what their rules allow, never an error or the owner's view (Task 3 test `a shared smart list is evaluated for its viewer`).
4. **A rule value with `%`, `_`, quotes or 500 characters** — matched literally, no SQL error (Task 3 test `contains matches text literally`).
5. **Random order between opening a smart video list and its "Up next"** — the next title follows the order the page showed (Task 3 test `random order holds between opening and playing`).

### Task 3: Smart playlists on the server

**Files:**
- Create: `src/library/smart.js`
- Modify: `src/lists.js`, `src/api/lists.js`
- Test: `test/smart.test.js` (rules, with an in-memory library), `test/smart-api.test.js` (routes)

**Interfaces:**
- Consumes: `user_ratings`, `plays` (Task 1–2), `Library.visibility(viewer)`.
- Produces: `validateRules(media: 'music'|'video', input) → { match: 'all'|'any', rules: Rule[], sort, limit: { items?: n } | { minutes?: n } | {} }` throwing `HttpError(400, sentence)`; `smartRows(db, library, list, viewer, { seed }) → item rows` (tracks also carry `album_title`, `album_poster` like `Library.tracks`).
- Rule `{ field, op, value }`. Fields — music (tracks): `genre, artist, albumArtist, album, year, stars, favourite, playCount, lastPlayed, added, length`; video (films and episodes): `genre, year, stars, favourite, playCount, lastPlayed, added, length, kind, ageRating`. Types: text (`genre, artist, albumArtist, album`) ops `is, isNot, contains`; number (`year, stars, playCount, length` (minutes, decimals ok), `ageRating` (`min_age`)) ops `is, isNot, gte, lte, between` (value `[a, b]`), and `set, notSet` for `year, stars, ageRating`; date (`added, lastPlayed`) ops `inLast, notInLast` (value days 1–3650), `set, notSet` for `lastPlayed`; `favourite` op `is` value boolean; `kind` op `is` value `movie|episode`. Text compare is case-insensitive; `contains` escapes `% _ \`. A track's genre/year fall back to its album's; an episode's genre/stars/favourite/age to its show's. Up to 20 rules; text values ≤ 200 chars.
- Sorts: `random, added, stars, mostPlayed, lastPlayed, title, year`. Random = `ORDER BY ((i.id * 2654435761 + seed) % 4294967296)`. Limit `{ items: 1–1000 }` or `{ minutes: 1–10000 }` (take in order while the total stays within N minutes; the first item is always taken). No limit → cap 1000.
- Error sentences (exact): `Rule N: Atomix doesn't know "<field>".`, `Rule N: "<op>" doesn't work with <field>.`, `Rule N: give a number.`, `Rule N: give two numbers, lowest first.`, `Rule N: give a number of days.`, `Rule N: give some text.`, `Choose how to sort.`, `A smart playlist has at most 20 rules.` (N counts from 1; `<field>` is the label the builder shows: "genre", "artist", "album artist", "album", "year", "stars", "favourite", "play count", "last played", "date added", "length", "kind", "age rating").
- `Lists.create(profileId, { kind: 'smart', name, media, rules })`, `Lists.setRules(id, { media?, rules })`; `Lists.rows(listId, viewer)` evaluates smart lists (seed from `this.seeds`, a Map `"<listId>:<profileId>" → seed` set to a new random value by `Lists.items` when the list is opened, kept otherwise); `visibleTo` lets any viewer see a shared smart list (evaluation filters it); `add`, `move`, `removeItem` on a smart list → `HttpError(400, 'A smart playlist fills itself — change its rules instead.')`; `forProfile` summaries count and poster smart lists for the viewer and add `media`.
- Routes: `POST /api/lists { kind: 'smart', name, media, rules }`; `PATCH /api/lists/:id { name?, shared?, media?, rules? }` (owner only); `GET /api/lists/:id` adds `media`, `rules` (the stored object) for smart lists.

  - `test/smart.test.js` (in-memory db, items inserted by SQL: 3 films with years/genres/min_age, 2 shows with episodes, 4 tracks over 2 albums; ratings and plays by SQL):
    - one test per type: `text rules` (genre is/isNot/contains, album artist), `number rules` (year between [1980,1990], stars gte 4, playCount is 0, length lte 3.5 min), `date rules` (added inLast 7, lastPlayed notInLast 30, lastPlayed notSet), `favourite and kind rules`, `episodes follow their show` (genre and stars from the show), `tracks follow their album` (year from the album).
    - `match any` returns the union; `match all` the intersection.

    - `contains matches text literally` — a genre `50%_Off "x"` matches `contains '%_O'` and nothing else; a 200-char value is accepted, 201 refused.
