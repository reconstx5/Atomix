# Atomix v0.27.0 Plan B: Live TV on phones

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phones get the most out of the encrypted channels they can play. Android gets a landscape full screen, a screen that stays on, a smaller buffer on mobile data, and a lower quality when HD is refused. A phone or browser that can't play a channel's protection says so before any stream starts. A FairPlay channel, if a playlist ever has one, plays in Safari through Atomix's relay.

**Architecture:**
- **Android polish:**
  - `views/phone-live.js` handles the wake lock and the orientation lock on touch devices, live channels only.
  - `dash/player.js` takes an `ahead` budget, and drops the levels whose keys the phone refuses. `dash/eme.js` reports those keys.
- **Can this device play it:** `dash/support.js` decides from the channel's system, the page's security, iOS and a cached key-system probe. The player asks it before starting an encrypted channel.
- **FairPlay:**
  - **The playlist:** IPTV Simple reads `license_type=com.apple.fps`.
  - **The server:** `src/live/hls-relay.js` rewrites HLS playlists so every address goes through the relay, and `LiveDrm` gains a `fairplay` system (master playlist, rewritten media playlists, the certificate, the licence with the content id).
  - **The browser:** `dash/fairplay.js` plays it in Safari through modern EME.

**Tech Stack:** browser EME (`com.widevine.alpha`, `org.w3.clearkey`, `com.apple.fps`), Screen Wake Lock, `screen.orientation`, Network Information. Node's test runner; Playwright checks in `/home/claude/devtools`.

**Spec:** `docs/superpowers/specs/2026-10-22-atomix-v027-phone-live-tv-design.md` (§2, Global constraints, Verification). Plan A is done: `NEED_SECURE`, `state.status.secureUrl`, and `v027-ui.mjs` with `withSite`, `signInAt`, `playing`, `PLAIN`, `SECURE`.

## Global Constraints

- **No DRM circumvention.** Decryption happens only in the device's own module. Provider addresses, headers, keys, tokens and the FairPlay certificate's URL never reach a browser, a TV or a log.
- **Nothing changes for other platforms.** New behaviour switches on only where it applies:
  - touch (`matchMedia('(pointer: coarse)')`) for the wake lock and the orientation lock;
  - mobile data for the buffer;
  - refused key statuses for the quality drop;
  - no Widevine, or an insecure page, for the new sentences;
  - `drm === 'fairplay'` for FairPlay.
- **Rules kept from v0.26:** Kids rules; the provider's stream limit and the account's 4 streams; encrypted channels are live only (no record, rewind or catch-up); the Encrypted badge.
- **No npm install, no build step, no new libraries.**
- **Older themes stay pixel-identical:** `oldthemes-compare.mjs compare` → "all pages match".
- **Each file in its own style:** the player is still a `render(el)` view; Live TV is a Preact screen (not touched here).
- **Copy, verbatim:**
  - "This channel is encrypted with Widevine, which iPhones can't play." (`NO_WIDEVINE_IPHONE`)
  - "This browser can't play this channel's protection." (`NO_WIDEVINE`, replacing "…(it has no Widevine)")
  - "This channel is encrypted with FairPlay, which plays in Safari on Apple devices" (`NO_FAIRPLAY`)
  - "This phone's protection won't play HD; playing a lower quality" (`LOWER_QUALITY`)
- **Values:**
  - buffer ahead **30 s**, **10 s** on mobile data (`saveData`, or `type === 'cellular'`);
  - FairPlay certificate at most **64 KB**, fetched within **10 s**;
  - HLS playlists at most **2 MB** (the manifest cap);
  - an HLS session's origins at most **64**, never reused.
- **Watch on TV is Plan C.** Plan B shows the sentences with Go back only. Plan C adds the button beside `NO_WIDEVINE_IPHONE` and `NO_WIDEVINE`, never beside `NO_FAIRPLAY`.
- **Process:** never `pkill -f`; browser suites one after another; restart the dev server (`restart-dev.sh`) after server changes; no git in the cloud copy (the ledger records each task).

## Review Focus

1. **Zapping on an iPhone from a Widevine channel to a plain one:** the plain channel plays, the iPhone sentence is gone, and no encrypted session was ever opened. Test: Task 4, `v027-ui nowv` "…zapping on to a plain channel plays it".
2. **A FairPlay master playlist and its media playlists on different hosts, with `../` paths and query strings:** every address goes through the relay, and the second host gets its own slot. Test: Task 3, `media playlists on another host resolve relative paths and keep their query`.
3. **A media playlist whose address has no `.m3u8`** (only an `application/vnd.apple.mpegurl` type): it is still rewritten, not passed through with provider addresses. Test: Task 3, `a playlist without .m3u8 is recognised by its type`.
4. **A wake lock that is refused** (battery saver, unsupported): playback goes on, with no console error and no notice. Test: Task 1, `v027-ui phone` "a refused wake lock changes nothing".
5. **Key statuses naming a key no level uses, or refusing every level:** an unknown key changes nothing (no notice, no drop); every level refused is still "This channel's protection won't play in this browser". Test: Task 1, `playableLevels ignores unknown keys and refuses when nothing is left`.
