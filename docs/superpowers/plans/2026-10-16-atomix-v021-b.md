# Atomix Round 23 — Plan B (on the device: install, the offline helper, Downloads) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Atomix installs like an app, downloads titles into the device's private storage in resumable pieces, and opens to a Downloads page that plays films, episodes and music with no connection, sending progress back when it can.

**Architecture:** A service worker (`public/sw.js`) keeps the app shell and answers `/offline/…` from the browser's private file storage (OPFS) with Range. `public/js/offline/` holds the storage index (IndexedDB) and files (`store.js`), the download manager (`downloader.js`), and the online sync (`sync.js`: checks, expiry, queued progress). The Downloads page, the Download buttons and the offline player/music sources use them. When `/api/status` can't be reached and this device holds downloads, the app boots offline: "Who's watching?" from a kept list (PINs checked against a kept PBKDF2 hash), then Downloads.

**Tech Stack:** plain ES modules, Service Worker, OPFS (`navigator.storage.getDirectory`), IndexedDB, WebCrypto; Playwright devtools on `localhost` (a secure context).

**Spec:** `docs/superpowers/specs/2026-10-16-atomix-v021-design.md` (section 2, Hard limits, Testing, Review focus). Consumes Plan A's routes (`docs/superpowers/plans/2026-10-16-atomix-v021-a.md`, archived ledger `scratchpad/note/v0210-progress-a.md`).

## Global Constraints

- Secure context only (`window.isSecureContext`): otherwise no service worker, no Download buttons; Settings → Profile's Install card says "Installing and downloads need a secure address (https:// or this computer's own localhost). On this address you can still save a file from a title's "…"."
- Files: OPFS `atomix-downloads/<profileId>/<itemId>.<ext>`, subtitles `<itemId>.<subId>.vtt`; index: IndexedDB `atomix` store `downloads` keyed `[profileId, itemId]` (item details for the page and player, poster thumbnail as a Blob, jobId, quality, format, size, bytes, status `preparing|downloading|paused|ready|failed|expired`, downloadedAt, checkedAt, position, duration, watched, subtitles `[{ id, label, language }]`); store `pending` (queued progress `{ profileId, itemId, position, duration, at }`); store `profiles` (the account's profiles from the last online picker: id, name, avatar, kids, hasPin, pinHash, pinSalt).
- Pieces: 8 MB Range requests, written at their byte offset; a resume asks from the bytes on disk and checks the `Content-Range` total equals the size the job reported and the job's `itemId` (else start again); up to 2 downloads at a time; only while the app is open.
- Space: limit = min(browser quota from `navigator.storage.estimate()`, the server's `downloadDeviceGb` from `/api/status`); "Using 3.2 GB of 20 GB"; a quota error → the download stops as `failed` with "This device is out of space for downloads", its partial file removed.
- Expiry: `check` on each online open and every 6 h; `remove` → deleted with a toast "Removed <title>: it's no longer available to download"; not checked for `offlineDays` → plays refuse with "Connect to Atomix to keep this download" (status `expired`); deleted 7 days after that.
- Kids: the same page and buttons; their own downloads only. PINs offline: PBKDF2-SHA-256, 100 000 rounds, 16-byte random salt, kept when a PIN is entered correctly online.
- Copy: buttons **Download**, **Downloaded**, **Remove download**; states "Preparing… 40%", "Downloading… 1.2 of 2.0 GB", "Paused", "Couldn't download"; page heading **Downloads**; offline banner "You're offline — your downloads are here".
- No browser dialogs; TV-remote friendly; older themes pixel-identical (new controls only where they add a button to the "…" sheet or a page that isn't in the compare set; the title page's Download button lives in "…" in older themes).

## Review Focus

1. **A download cut off mid-file and resumed** — the file plays to the end with no gap (Task 3 UI check `resume after the network drops`).
2. **An account switched off, or a title re-rated above a Kids profile's age, while a device was offline** — removed at the next online check, never played after the offline period (Task 6 check `check removes, expiry refuses`).
3. **The service worker after an Atomix update** — no old shell with a new API, never swapped mid-playback (Task 1 test `a new version waits for the next open`).
4. **A full device** — "This device is out of space for downloads", nothing half-indexed (Task 3 check `out of space`).
5. **Two profiles on one device with the same title** — each sees only its own; removing one keeps the other (Task 4 check `two profiles, one title`).
