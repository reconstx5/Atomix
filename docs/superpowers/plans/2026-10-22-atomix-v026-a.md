# Atomix v0.26.0 Plan A: the Preact foundation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preact and htm kept in the repo (no npm install, no build step), with a router adapter, `useAppState()` and the first building blocks. Each block draws exactly what today's helper draws, so Plan B can move the pilot screens with no visible change.

**Architecture:**
- The vendor files live in `public/js/vendor/`, with their imports rewritten to relative paths by a devtools script.
- `public/js/ui.js` is the one place components import from.
- The router mounts either an old `render(el)` view or a `Screen` component through `public/js/screen.js`.
- App-state changes come from a Proxy in `public/js/state-events.js`.
- The building blocks in `public/js/ui/` mirror `components.js`'s helpers.

**Tech Stack:** Preact 11.0.1 (MIT), htm 3.1.1 (Apache-2.0), plain ES modules. Node's test runner; Playwright checks in `/home/claude/devtools`.

**Spec:** `docs/superpowers/specs/2026-10-22-atomix-v026-preact-foundation-design.md` (§1, Global constraints, Verification).

## Where this plan departs from the spec

1. **htm's licence is Apache-2.0**, not MIT, as its package says. Both licences allow keeping the code in the repo; `LICENSES.md` carries both texts.
2. **Four vendor files, not three.** htm's Preact entry imports htm's core, so `htm.module.js` is kept too.
3. **State changes come from a Proxy** (`watchState`) rather than calls sprinkled where `app.js` changes state. It catches every top-level write; `notifyState` covers nested ones.
4. **Building blocks:**
   - **Sheet and Toast stay plain function calls** (`openSheet`, `toast`), because they open dialogs and toasts rather than drawing in place. Wrapping them as components would add nothing.
   - **The live-page pieces** (`ChannelCard`, `LiveSpotlight`, `AzRail`) move in Plan B with the screens that own them.
   - **`Grid` covers poster, square, landscape and live items for now.** Its `list` and `apps` styles come with the screens that use them in later rounds.

## Global Constraints

- **"No npm install, no build step."** Only Preact (with `preact/hooks`) and htm are kept in the repo, in `public/js/vendor/`, pinned, with licences and `checksums.json`. ARCHITECTURE.md states the rule.
- The kept files import each other by relative path. Atomix imports them by path. **No import map.**
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match".
- No screen changes in this plan: every existing check stays green as it is.
- **Unchanged:** `nav.js`, the CSS and theme classes, the server API, the pure rule files and the engines.
- Never `pkill -f`. Run browser suites one after another.

## Review Focus

1. **A view that throws while mounting, or a route change while a `Screen` is still loading.** The old screen is cleaned up exactly once and the new one mounts; nothing leaks or renders into a stale container. Test: Task 2, `a superseded or failing Screen is cleaned up and never shown`.
2. **Nested state changes (`state.profile.prefs.theme = …`) that the Proxy can't see.** `applyTheme()` and profile switches still notify. Test: Task 2, `useAppState updates on a theme change and a profile switch, not on an unrelated key`.
3. **Boolean and empty attributes** (`hidden`, `data-autofocus`, `aria-pressed="false"`, `disabled`) drawn differently by Preact than by `h()`. Each block's markup equals the helper's. Test: Task 3, the `blocks match` checks with those attributes in their inputs.
4. **Offline (installed app):** the vendor files are in the offline helper's file list, so a converted screen opens offline. Test: Task 1, `the offline file list carries the vendor files`.
5. **`cardItems` registration on a re-rendered card.** The backdrop and spotlight still find the item after a re-render with a new item object. Test: Task 3, `a re-rendered card points cardItems at its new item`.

**Interfaces:**
- Produces:
  - **`state-events.js`:**
    - `watchState(target: object) → Proxy`: setting a top-level key to a new value (`!Object.is`) calls the listeners with that key;
    - `onState(fn: (key) => void) → () => void` (unsubscribe);
    - `notifyState(key: string): void`, for nested changes the Proxy can't see.
  - **`ui.js`:**
    - re-exports `html`, `render`, `h` (Preact's) and `useState`, `useEffect`, `useRef`, `useMemo`, `useCallback`, `useLayoutEffect`;
    - exports `useAppState(select: (state) => any) → any`, which re-renders when `select(state)` changes (`Object.is`), checked on every `onState` event.
  - **`screen.js`:** `mountView(container: HTMLElement, mod, params, query) → Promise<(() => void) | null>`.
    - With `mod.Screen`, it renders `html\`<${mod.Screen} params=${params} query=${query} />\`` into `container` and returns `() => render(null, container)`.
    - Otherwise it returns what `mod.render(container, params, query)` returns, if that is a function.
  - The router's existing token check still drops a superseded result: it calls the returned cleanup and doesn't show the container.

- Modify: `v026-ui.mjs` section `blocks`.

**Interfaces:**
- Consumes: Task 2's `ui.js`.
- Produces (props mirror the helpers' arguments):
  - **`basics.js`:**
    - `Button({ label, icon, variant = 'secondary', onClick, href, autofocus, title, type = 'button', attrs = {} })`, the same as `button()`;
    - `EmptyState({ title, text, action, icon = 'film', level = 2 })`, where `action` is a vnode;
    - `MoreButton({ title, items })`, which opens `openSheet(title, items)`;
    - `Spinner({ label = 'Loading', inline = false, size = 18 })`.
  - **`cards.js`:**
    - `PosterCard({ item })`, `SquareCard({ item })`, `LandscapeCard({ item, play = true })` and `LiveCard({ item })`, each setting `cardItems` for its element in a ref callback (also when the item prop changes);
    - `Grid({ items, style = 'poster' })`, with the same branch choice as `cardFor` for `poster | square | landscape` and `kind === 'live'` items. `list` and `apps` aren't supported yet: a later round adds them with the screens that use them.
    - `Row({ title, subtitle, items, style, href, id, inMenu })`;
    - list children carry `key={item.id}` (or the index when there's no id).
  - **`spotlight.js`:** `Spotlight({ item, onShow, quiet = false })` draws `spotlight()`'s markup for `item`, including `playAs`, `seasonCount` (via the meta line), trailer and resume. It calls `onShow(item)` after the item changes, and replays the fade unless `quiet`.
    - The logo shows on its image's load event, as today.
    - The primary button keeps `data-autofocus`.
    - Preact keeps the buttons' elements between items, so focus isn't lost.
