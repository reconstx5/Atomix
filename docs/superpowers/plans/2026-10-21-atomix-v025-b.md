# Atomix v0.25.0 Plan B: Orbit's Movies and TV Shows pages, and the release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Orbit, Movies and TV Shows libraries get Home's spotlight following the remote, one glass control bar with sheets, progress lines on posters and an A–Z rail. Then v0.25.0 ships with its pictures.

**Architecture:**
- `views/library.js` keeps today's page for older themes and for every other library type. It builds the Orbit page only when `isOrbit()` and the library is `movies` or `tv`.
- Pure rules live in `public/js/library-rules.js`; the rail is `public/js/az-rail.js`.
- The spotlight is Home's `spotlight()`, given two small options. A title's trailer, season count and next episode come from `/api/items/:id`, fetched when the spotlight shows it and cached.
- One read-only route, `GET /api/libraries/:id/recent`, supplies "most recently watched and not finished". Items also gain `sortTitle`.

**Tech Stack:** Node ≥ 22.13, node:sqlite, plain ES-module browser JS, no build step. Playwright checks in `/home/claude/devtools`.

**Spec:** `docs/superpowers/specs/2026-10-21-atomix-v025-orbit-livetv-library-design.md`, §2, Verification and Plans.

## Global Constraints

- Node ≥ 22.13; plain ES-module browser JS with no build step; **no dependencies**; no copied icons or skins.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match". Every change is Orbit-only (`isOrbit()` in the views, `body[data-layout="orbit"]` or `themes/orbit/theme.css` in CSS).
- Server changes: none were planned in the spec, but its spotlight's "Resume S1 · E3" first title and its "3 in progress" can't be worked out from what the listing sends. This plan adds one read-only route and one field (Task 1), with Kids rules applied by the existing visibility filter. Ledger this as a ruling.
- Kids profiles keep their rules: their titles only.
- Every control works with a remote (D-pad, Select, Back), a mouse, touch and a screen reader. Text and focus keep the contrast Orbit's checks already measure.
- The URL keeps sort, genre, unwatched and search (Back returns to the same view); the Collections view, the backdrop following focus and the other library types are unchanged.
- Never `pkill -f`; kill by PID. Browser suites share one dev user: run them one after another, never in parallel.

**Interfaces:**
- Produces:
  - `GET /api/libraries/:id/recent` → `[{ id: number, at: number }]`.
    - `id` is the film's id, or the show's id for an episode.
    - Built from `library.continueWatching(viewer, 200)` and `library.nextUp(viewer, 200)` (their `updated_at` / last-watched time as `at`), kept to this library, with one entry per id (the newest), newest first, at most 50.
    - `[]` for libraries that aren't `movies` or `tv`, and for no profile.
    - It goes through `visibleLibrary(ctx, id)` like the items route.
  - Items carry `sortTitle` (string or null).
  - `library-rules.js` exports:
    - `letterOf(item) → 'A'…'Z' | '#'`: the first character of `item.sortTitle ?? sortKey(item.title)`, accents folded (NFD, marks stripped) and upper-cased; anything not A–Z is `'#'`.
    - `sortKey(title) → string`: the same as `src/library/parser.js` `sortTitle` (lower case, leading the/a/an dropped, punctuation dropped, trimmed). Copy it; the browser can't import server files.
    - `railLetters(items) → string[]`: each item's letter in list order, without repeats.
    - `jumpIndex(items, letter) → number`: the index of the first item with that letter, or -1.
    - `railShown({ sort, q, count }) → boolean`: `sort === 'title' && !q && count >= 20`.
    - `inProgress(item) → boolean`:
      - a film is in progress with `progress.position > 30` and not watched;
      - a show is in progress with `0 < unwatched < childCount`.
    - `posterFraction(item) → number | null`: a film's `position / (progress.duration || duration)`; a show's `(childCount - unwatched) / childCount`; null when not `inProgress`.
    - `countLine(n, inProgressCount, [one, many]) → string`: "42 shows · 3 in progress", "1 movie", "42 shows" (the second part only when > 0).
    - `spotStartItem(items, recent) → item | null`: the item whose id comes first in `recent`, else `items[0]`, else null.
    - `playFor(item, details) → { label, href, position, duration } | null`, for the spotlight's primary button:
      - a film: "Resume" with `item.progress` when `position > 30` and not watched, else "Play"; href `#/play/<id>`;
      - a show with `details.nextEpisode` (call it `e`):
        - "Resume S1 · E3" when `e.progress.position > 30`;
        - "Play S1 · E4" when `inProgress(item)`;
        - "Play" otherwise;
        - href `#/play/<e.id>`;
      - a show without `details`: null (the component keeps "Open" until details arrive).
