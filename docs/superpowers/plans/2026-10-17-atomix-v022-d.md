# Atomix v0.22 Plan D — Books and comics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Books (EPUB) and Comics (CBZ, CBR, CB7, folders of images) libraries, read on a phone or tablet first (a TV remote still works), online and offline, with per-profile progress that follows the reader across devices.

**Architecture:**
- One dependency-free ZIP reader in `public/js/reader/zip.js`, shared by three users:
  - the server, which inflates with `zlib`;
  - the browser, which inflates with `DecompressionStream`;
  - the offline helper (service worker), which serves downloaded books.
- Two new library types, `books` and `comics`, use the existing machinery: items, series as `show_id` parents, `canSee`, progress, plays, search, lists and Downloads.
- EPUB chapters are served by Atomix with a script-free CSP into a sandboxed frame that has no `allow-scripts`. The app paginates them with CSS columns.
- Comic pages are served one entry at a time. CBR and CB7 come through an optional 7-Zip or unrar that Atomix finds.

**Tech Stack:** Node ≥ 22.13 (`node:sqlite`, `zlib.inflateRawSync` with `maxOutputLength`, `zlib.crc32`), ffmpeg for covers and page scaling, plain ES-module browser JS, `DecompressionStream('deflate-raw')`, and the DOM-free XML reader at `public/js/dash/xml.js`.

**Spec:** `docs/superpowers/specs/2026-10-17-atomix-v022-design.md` §4 (Books and comics), with the global constraints.

## Global Constraints

- Node ≥ 22.13, `node:sqlite`, ffmpeg; plain ES-module browser JS; **no dependencies** (7-Zip/unrar are optional external tools, like ffmpeg).
- No Kodi GPL code. No DRM circumvention.
- Kids profiles never see admin data, and never see a title outside their rules (age rating, allow-unrated, libraries).
- Older themes stay pixel-identical: `node devtools/oldthemes-compare.mjs compare` → "all pages match".
- **Book content never runs scripts.**
- ZIP limits: 50 MB per entry, inflated ≤ 100× its packed size, ≤ 5,000 entries; damaged files are refused with a sentence, not a crash.
- External tools are run with arguments as an array, never a shell; entry names are checked against the cached list.
- PDF is out of scope.
- No online lookup for books or comics this round.

## Decisions this plan makes (the spec leaves them open)

- **Series:**
  - Comics take their series from ComicInfo `Series`, else the folder name.
  - Books take it from `belongs-to-collection` or `calibre:series` only. A book with neither stands alone: a book folder is usually its author.
  - A series is an item of kind `series` in the same library. Issues and books point to it with `show_id`, so an unrated issue inherits its series' rating, as an episode does from its show.
- **Issue numbers:**
  - `items.issue` (TEXT: "1", "1.5", "Annual 2") and `items.issue_sort` (REAL).
  - Taken from ComicInfo `Number`, else the first number in the file name after the series name (`Saga 012 (2013).cbz` → "12").
- **Position:**
  - `progress.locator` (JSON) and `progress.device` (TEXT: "phone", "tablet", "computer" or "TV", from the reporting client).
  - Books: `progress.position` is percent read (0–100) and `duration` is 100. The locator is `{ "chapter": <spine index>, "offset": <character offset into the chapter's text> }`.
  - Comics: `progress.position` is the page index and `duration` is the page count. The locator is `{ "page": n }`.
  - A book or comic is Read only when the reader reports past its last page (`watched: true`). There is no 90% rule for reading.
- **Time and pages read:**
  - The reader reports through the existing play history every 30 s while the page is visible.
  - `plays.pages` (migration 26) counts pages turned.
  - Stats gain `readHours` and `pagesRead`.
- **Downloads:** a book downloads as its `.epub` file. A comic always downloads as a CBZ: a CBZ is copied as it is; a CBR, a CB7 or a folder comic is packed into a stored (uncompressed) ZIP by the server.
- **Offline reading:** the offline helper serves `/offline-zip/<profile>/<file>/<entry>` from the downloaded file using `reader/zip.js`. The readers use the same URLs online and offline: only the base address changes.
- **Large pages:** a comic page whose longer side is over 4000 px is scaled once by ffmpeg to 2400 px (cached under `cacheDir/comic-pages`). Zooming past that size fetches `?full=1`.
- **Reading speed:** "min left in chapter" assumes 250 words a minute until this device has measured the reader (words over time on page, kept in localStorage).

## Review Focus

1. **A hostile archive** — a ZIP bomb, `../` or absolute entry names, duplicate names, or an entry claiming 4 GB. It is refused with a sentence, and nothing outside the cache is ever written. *(Task 1 test.)*
2. **An EPUB with scripts, forms, iframes, SVG `<script>`, or remote fonts and images** — nothing runs and no request leaves Atomix. *(Task 4 test of the CSP header; Task 5 browser check.)*
3. **Changing text size, or rotating the phone, mid-chapter** — the same sentence stays on screen. Position is a text offset, not a page. *(Task 5 check.)*
4. **A Kids profile and a comic series with mixed ratings** (series unrated, one issue rated 18) — only allowed issues show, and Continue reading never shows another. *(Task 4 test.)*
5. **A CBR whose 7-Zip went away after the scan, or a tool that hangs** — the page answers a sentence within 30 s, never a stuck request. *(Task 3 test.)*

### Task 1: The ZIP reader

**Files:**
- Create: `public/js/reader/zip.js`. It has no imports and is isomorphic. `/sw.js` concatenates it, so every `export` must sit at the start of a line.
- Create: `src/books/zip.js` (the server side).
- Create: `src/books/zip-write.js` (a stored-ZIP writer, for CBZ packing in Task 4).
- Test: `test/zip.test.js` (fixtures built in the test with a small hand-written ZIP builder; no binary files).

**Interfaces — Produces:**
- `ZIP_LIMITS = { entryBytes: 52428800, ratio: 100, entries: 5000 }`.
- `class ZipError extends Error`. It carries one of these exact messages:
  - "This file is damaged or isn't a ZIP archive."
  - "This archive has more than 5,000 files."
  - "A file in this archive is too large to open."
  - "This archive uses a kind of compression Atomix can't read."
  - "This archive has a file name Atomix won't open."
- `readZipIndex(read, size, limits = ZIP_LIMITS) → Promise<Map<string, Entry>>`
  - `read(offset, length) → Promise<Uint8Array>`.
  - `Entry = { name, method, packed, size, offset, crc }`.
  - Handles ZIP64, the end record and the locator.
  - Refuses names that are absolute, contain `..` segments or NUL, or appear twice.
- `readEntry(read, entry, inflate, limits = ZIP_LIMITS) → Promise<Uint8Array>`
  - `inflate(bytes, maxOutput) → Promise<Uint8Array>`.
  - Method 0 or 8 only.
  - Size checks happen before inflating: `size > entryBytes`, or `size > packed × ratio` (packed 0 counts as 1).
  - The output length must equal `entry.size`.
- `openZip(file) → Promise<{ entries: Map, read(name) → Promise<Buffer>, close() }>` in `src/books/zip.js`.
  - Uses `zlib.inflateRawSync(buf, { maxOutputLength })`.
  - An LRU of 16 open indexes, keyed by path, mtime and size.
- `writeStoredZip(outFile, files: [{ name, file? , data? }]) → Promise<void>` in `src/books/zip-write.js`. CRC from `zlib.crc32`; ZIP64 not needed (comics stay under 4 GB; refuse past that with ZipError's "too large" sentence).
