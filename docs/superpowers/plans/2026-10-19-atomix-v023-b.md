# Atomix v0.23.0 Plan B — Info and artwork plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four plugins that can be switched on in Settings → Plugins (`fanart-tv`, `omdb-ratings`, `open-library`, `musicbrainz`) and fill in logos, artwork, outside scores, book details and album details. They only fill gaps, are kind to each service, and keep working when the network doesn't.

**Architecture:** Each plugin is a metadata provider. Merge order decides who wins: TMDB is 50, and the new plugins run after it (MusicBrainz 55, Fanart.tv 60, Open Library 60, OMDb 70), so they only fill what is still empty. A shared helper `plugins/_lib/service.js` keeps the four consistent: one request at a time with a minimum gap, timeouts, JSON, a result cache in `api.storage`, a failure logged once per outage, and failed titles offered again at the next scan. Small core additions (`api.setStatus`, `api.metadataLanguage`, `api.metadata.offerAgain`) let a card say "paste your key" and let a key added later reach titles already scanned.

**Tech Stack:** Node ≥ 22.13, `node:test`, global `fetch`, plain ES modules. No dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-atomix-v023-plugins-design.md` (§2; §1 for the core it builds on). Plan A is complete. ## Global Constraints

- Node ≥ 22.13, `node:sqlite`, ffmpeg; plain ES-module browser JS; **no dependencies**. No Kodi GPL code.
- Keys and tokens (Fanart.tv, OMDb) never reach the browser or the logs. They are `password` settings; nothing logged includes a request URL that carries a key.
- Plugins only fill gaps: what files, `.nfo`s, Edit details or TMDB already gave stays. Locked fields stay locked. Books and audiobooks are fill-only in core (Plan A).
- Every plugin works with no network: a lookup that fails is logged once and tried again at the next refresh, never breaking a scan.
- Tests reach fake services only. Base addresses come from `ATOMIX_FANART_BASE`, `ATOMIX_OMDB_BASE`, `ATOMIX_OPENLIBRARY_BASE`, `ATOMIX_MUSICBRAINZ_BASE` and `ATOMIX_COVERART_BASE`.
- Each plugin is off until turned on (`"enabledByDefault": false`). Where a key is needed and missing, it does nothing and its card says so.
- Results are kept in the plugin's storage, so a rescan doesn't ask again. Refresh info (`ctx.force`) asks again.
- Open Library and MusicBrainz: at most one request a second.
  - Open Library User-Agent: `Atomix/<version>`.
  - MusicBrainz User-Agent: `Atomix/<version> ( <contact email setting> )`, or `Atomix/<version>` when the setting is empty. The setting has no default value.
- Older themes stay pixel-identical: `node /home/claude/devtools/oldthemes-compare.mjs compare` → "all pages match".

## Review Focus

1. **The service is down, slow or answers 5xx during a scan.** The scan finishes, one log line says so, and those titles are filled at the next scan. Tests: Task 1 `a failure is logged once and the title is offered again at the next scan`; Task 2 `Fanart.tv down: the scan finishes and the logo comes at the next scan`.
2. **A key is pasted after the library was scanned.** Existing titles get filled at the next scan, without waiting for Refresh info. Test: Task 2 `adding the key later fills titles scanned before it`.
3. **An album whose only cover is the one embedded in its tracks.** MusicBrainz and Fanart.tv leave it alone. Test: Task 5 `an embedded album cover stays`.
4. **Names with quotes, slashes or Lucene characters** (AC/DC, `Live "Here"`). The MusicBrainz query is escaped and still matches. Test: Task 5 `names with quotes and slashes are escaped`.
5. **The OMDb daily limit runs out mid-run, then the day changes.** It stops asking, says so on the card, and carries on the next day. Tests: Task 3 `the daily limit stops lookups and the titles wait` and the pure `usageAllows` day-rollover test.

**Interfaces:**
- Produces, on the plugin api:
  - `api.setStatus(text: string|null)`: a sentence shown on the plugin's card while it's on. `null` clears it. It is held in memory, so each plugin sets it again in `setup()`.
  - `api.metadataLanguage`: a getter for the server's `metadataLanguage` setting (e.g. `'en-US'`).
  - `api.metadata.offerAgain(ids?: number[]) → number`: sets `metadata_at = NULL` for those items (all of them when `ids` is omitted). It only touches items whose kind one of this plugin's providers lists, and only where `metadata_locked = 0`. The next scan's metadata pass fills them. It returns the count.
  - `/api/admin/plugins` entries gain `status: string|null`.
- Produces, from `plugins/_lib/service.js`: `createService(api, opts) → service`.
  - `opts`: `{ name: string, base: () => string, gapMs = 0, timeoutMs = 15000, headers: () => object }`.
  - `service.json(pathOrUrl: string, { query?: object } = {}) → Promise<object|null>`:
    - `null` on 404;
    - throws a `ServiceError { kind: 'auth'|'limit'|'down', status }` on 401/403, on 429, and on 5xx/network/timeout respectively.
    - The error's `message` never contains the URL or query.
  - `service.cached(key: string, { force: boolean }, fn: () => Promise<value|null>) → Promise<value|null>`:
    - storage key `cache:<key>`;
    - a found value is kept until `force`;
    - a `null` (not found) is kept for 30 days;
    - a thrown error is not kept.
  - `service.failed(item, err)`: for `down` and `limit`, notes `item.id` for a retry and logs at most once until the next success: `<name> can't be reached (<detail>); titles are tried again at the next scan.` For `auth`, calls `api.setStatus(`${name} refused the key. Check it in the settings below.`)`. It never throws.
  - `service.ok()`: marks the outage over, so the next failure is logged again.
  - `service.start()`: registers a `scan:complete` handler that calls `api.metadata.offerAgain([...noted])` and clears the noted ids. Also called on cleanup.

- Produces:
  - `export function toScores(omdb) → [{ source, value }]`. "Internet Movie Database" → `imdb`, "Rotten Tomatoes" → `rt`, "Metacritic" → `metacritic`. `N/A` is skipped. When `Ratings` has no IMDb entry, `imdbRating` gives `<r>/10`.
  - `export function usageAllows(usage, today, limit) → { ok: boolean, usage }`. `usage` is `{ day, count }`; a different `day` starts again at 0.
  - `today` is `new Date().toLocaleDateString('en-CA')` (server local).
  - Provider `{ id: 'omdb-ratings', name: 'OMDb', priority: 70, kinds: ['movie', 'show'] }`. It returns `{ scores }` only.

**Behaviour:**
- Requests: base `ATOMIX_OMDB_BASE` or `https://www.omdbapi.com`, as `/?apikey=<key>&i=<imdbId>`. With no IMDb id, `&t=<title>&y=<year>&type=movie|series`, and a result whose `Year` differs from a known year by more than 1 is taken as not found.
- Answers:
  - `{"Response":"False","Error":"…not found!"}` is not found (cached for 30 days).
  - `Invalid API key!`, or a 401, is `auth`.
  - `Request limit reached!` sets today's count to the limit (`limit`).
- Every request counts against the day. With the limit used, it doesn't ask: it calls `service.failed(item, limitErr)`, so the title waits for a later scan, and sets the status to `Today's limit of <n> lookups is used up; scores carry on tomorrow.`
- Status otherwise:
  - no key: `Paste your free OMDb key to start.`;
  - else `null`.
- When the key changes to a non-empty value, it calls `offerAgain()`.
- **Fetch missing scores:**
  - no key: `{ message: 'Add your OMDb key first.' }`;
  - none missing: `No titles are missing scores.`;
  - already running: `Already fetching scores (<done> of <total>).`;
  - else it starts a background run and returns `Fetching scores for <n> titles in the background.`
- The run refreshes 3 at a time with `api.metadata.refresh(id)` and stops before the limit. When it ends, the status says one of:
  - `Last fetch: scores for <got> of <total> titles.`, or
  - with the limit hit, `Last fetch: scores for <got> of <total> titles; the daily limit stopped it, the rest follow tomorrow.`, after `offerAgain(rest)`.

- Cache key `isbn:<isbn>` or `ta:<title>|<author>`.

- **Album:**

  - It takes the first with `score ≥ 90`, `normName(title)` equal to the album's, and some `artist-credit[].name` normalising to the album artist. For "Various Artists" the artist check is skipped.
  - Then `GET /ws/2/release-group/<id>?inc=genres` for genres: top 3 by count, first letter capitalised.
  - Returns:
    - `musicbrainzId`;
    - `year`, from `first-release-date`, only when the row has none;
    - `genres`, only when the row has none;
    - `poster: `${cover}/release-group/<id>/front-500``, only when neither the row (which may hold the embedded cover, `cache:emb-…`) nor `ctx.merged` (a folder cover) has a poster, **and** the Cover Art Archive lists a front image: `GET ${cover}/release-group/<id>` (no rate gap; 404 = none) has an image with `front: true`. Without that check, an album with no CAA cover would pass a dead address as `poster` and block Fanart.tv's cover.
- **Artist:**
  - `GET /ws/2/artist/?query=artist:<q(name)>&limit=5`, taking `score ≥ 90` with an equal `normName`.
  - Returns `{ musicbrainzArtistId }`.
  - "Various Artists" and "Unknown artist" aren't looked up.
- The ids are returned even when there's nothing to fill, so Fanart.tv can use them. They come from the cache (key `rg:<artist>|<title>`, `ar:<name>`), so a rescan asks nothing.
- User-Agent: `Atomix/<version> ( <contact> )` when `contact` is set, else `Atomix/<version>`.
